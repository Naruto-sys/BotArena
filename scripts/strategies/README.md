# Проверочные стратегии

Откройте [локальную арену](http://127.0.0.1:5050), выберите **Дозорного**, вставьте содержимое файла целиком вместо примера и нажмите **Запустить матч**. Для просмотра движения установите скорость 0,5× или перематывайте реплей по кадрам.

| Файл | Что должно произойти |
| --- | --- |
| [cover-skirmisher.js](cover-skirmisher.js) | Боевой бот для гусеничного шасси «Танк»: строит маршрут вокруг стен, прогнозирует несколько манёвров, уходит с траекторий пуль, меняет укрытия при перезарядке и выходит из застреваний задним ходом. Стреляет с упреждением на ходу; после потери цели исследует новые позиции. |
| [wall.js](wall.js) | Синий танк едет прямо в центральное укрытие, останавливается перед ним и через две секунды игрового времени начинает сдавать назад. Команды остаются валидными. |
| [arena-edge.js](arena-edge.js) | Танк сдаёт назад и останавливается у левой границы. Корпус остаётся внутри арены. |
| [reverse.js](reverse.js) | После резкой команды заднего хода танк продолжает ехать вперёд, тормозит, проходит через нулевую скорость и разгоняется назад. |
| [steering.js](steering.js) | Танк разворачивается на месте в обе стороны. После 1,2 с команды меняются каждый тик. Инерция гасит резкие смены направления корпуса и башни, центр танка остаётся на месте. |
| [clamped-tracks.js](clamped-tracks.js) | Тяга 500 ограничивается до 1. Танк движется с обычной скоростью и останавливается у стены. |
| [invalid-action.js](invalid-action.js) | Строка вместо числовой тяги вызывает ошибку на тике 8. Движение до ошибки доступно в реплее. |
| [instruction-limit.js](instruction-limit.js) | Бесконечный цикл прерывается, под редактором появляется сообщение о лимите исполнения. |
| [tick-timeout.js](tick-timeout.js) | Нативное ожидание на 250 мс расходует бюджет времени вызова. После контрольной точки Jint возвращает ошибку стратегии. Номер тика может отличаться. |
| [worker-timeout.js](worker-timeout.js) | Нативное ожидание на 7 секунд блокирует исполнение. Примерно через 5 секунд сервер останавливает рабочий процесс и показывает ошибку. После этого можно запустить обычную стратегию. |
| [sandbox.js](sandbox.js) | Бой завершается без ошибки стратегии. Тест проверяет отсутствие API Node, CLR и `fetch`, а также что `eval` и конструктор `Function` не запускают код. |

Автоматическая проверка использует те же файлы. Из корня репозитория при работающем сервере:

```sh
python3 -B scripts/validate_strategies.py
```

Отдельная проверка боевой стратегии (нужен запущенный сервер):

```sh
python3 -B scripts/validate_skirmisher.py
# Для сравнения с предыдущим кодом:
python3 -B scripts/validate_skirmisher.py --baseline /path/to/previous.js
```

Проверяются реальные матчи против встроенных соперников, открытая линия огня,
старт у стены, выход из П-образного укрытия и затяжной бой на 500 тиков.
Скрипт выводит HP, полученные попадания, пройденный путь и максимальную
неподвижность. Стратегия рассчитана на стандартные размеры танка и скорость
снаряда 13 единиц/с; под другие шасси потребуется адаптация модели движения.

На карте MVP за тик (50 мс) танк проезжает не больше 0,18 ед. вперёд, разворачивает корпус не больше чем на 0,15 рад и башню не больше чем на 0,30 рад. При реверсе вдали от препятствий тест проверяет ограниченное изменение продольной скорости. Столкновение останавливает танк сразу. Корпус и башня плавно набирают угловую скорость.

Команда `dotnet test tests` запускает прямые проверки движка и Jint с этими же стратегиями. Проверки дедлайна рабочего процесса идут через HTTP, поскольку его останавливает сервер.

Проверки среды подтверждают конкретные запреты API и два уровня ограничения времени. Jint проверяет бюджет между операциями. Дедлайн рабочего процесса нужен для блокирующей операции, внутри которой такая проверка не выполняется. Рабочий процесс запускается с правами локального пользователя, поэтому эти сценарии не подтверждают изоляцию на уровне ОС.
