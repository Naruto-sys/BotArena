# BotArena

Учебная платформа для боёв программируемых танков. Напишите стратегию на JavaScript, выберите встроенного противника и запустите дуэль. Сервер C# полностью рассчитает бой, а интерфейс React воспроизведёт его по кадрам.

## Локальный запуск

Нужны .NET SDK 10, Node.js 22.12+ и npm.

```sh
npm --prefix frontend ci
npm --prefix frontend run build
dotnet run --project server
```

Откройте [http://127.0.0.1:5050](http://127.0.0.1:5050). Для разработки фронтенда запустите `npm --prefix frontend run dev` в отдельном терминале с работающим сервером и откройте [http://127.0.0.1:5173](http://127.0.0.1:5173).

## PostgreSQL и Yandex ID

Раздел «Сообщество» хранит пользователей, стратегии, версии и библиотеку манёвров в PostgreSQL. Для локального запуска поднимите базу и укажите настройки авторизации:

```sh
docker compose -f server/compose.postgres.yml up -d
```

Создайте `server/appsettings.Local.json` по примеру `server/appsettings.Local.example.json`. Этот файл исключён из Git. В приложении Yandex OAuth запросите права `login:info` и `login:avatar`, а Callback URL задайте **точно** как `http://localhost:5050/auth/callback` для локальной разработки. Протокол, домен, порт и путь должны совпадать посимвольно. В production используйте HTTPS и соответствующий публичный адрес.

Те же настройки можно передать переменными среды:

```text
ConnectionStrings__BotArena=Host=localhost;Port=5432;Database=botarena;Username=botarena;Password=...
Database__MigrateOnStartup=true
Authentication__Yandex__ClientId=...
Authentication__Yandex__ClientSecret=...
Authentication__Yandex__CallbackPath=/auth/callback
```

При запуске сервер применяет миграции EF Core. После первого входа через Yandex ID пользователь обязан выбрать уникальный ник. Имя, фамилия и фотография профиля обновляются из Yandex ID при последующих входах.

Новый пользователь получает 1000 виртуальных кредитов. Кредиты можно получить за победы в дружеских боях на ставку и продажу опубликованных стратегий. Все списания и начисления записываются в журнал операций PostgreSQL; при ничьей или техническом сбое боя ставки возвращаются обоим игрокам.

## Python в редакторе

По умолчанию доступен JavaScript. Чтобы включить Python на macOS или Linux (ARM64 или x86-64), установите среду из корня репозитория. Для установщика нужен Python 3.11+.

```sh
python3 scripts/install_python_runtime.py
BOTARENA_PYTHON_RUNTIME="$PWD/.botarena/python" dotnet run --project server
```

Запускайте сервер от обычного пользователя. Установщик скачивает закреплённые версии CPython WASI и Wasmtime и сверяет SHA-256. После перезапуска выберите **Python** в поле «Язык стратегии». Редактор подставит пример и будет хранить отдельный черновик для каждого языка до перезагрузки страницы.

```python
def tick(state):
    return {"leftTrack": 1, "rightTrack": 1}
```

Поля команды одинаковы в обоих языках. В Python состояние и вложенные объекты приходят как словари, массивы как списки, а скрытый противник обозначен `None`.

## Стратегия

Редактор содержит готовую стратегию. Минимальный бот остаётся на месте и ведёт огонь по видимой цели:

```js
function tick({ self, enemy }) {
  if (!enemy) return {};
  const x = enemy.position.x - self.position.x;
  const y = enemy.position.y - self.position.y;
  const error = Math.atan2(y, x) - self.turretAngle;
  return {
    aimDirection: { x, y },
    shoot: self.canShoot && Math.abs(Math.atan2(Math.sin(error), Math.cos(error))) < 0.05
  };
}
```

`leftTrack` и `rightTrack` задают тягу гусениц в диапазоне от −1 до 1. Можно проще: `driveTo: { x, y }` и `aimAt: { x, y }`, либо хелперы `driveTo(self, point)`, `aimAt(self, point)`, `facing(self, point)`. Пропущенные команды эквивалентны нулевой тяге, сохранению направления башни и отсутствию выстрела. Состояние JavaScript сохраняется между тиками одного матча. `enemy` равен `null`, когда между центрами танков стоит стена.

Для непрерывного вращения башни вместо `aimDirection` используйте `turretTurn`
от −1 до 1: положительное значение вращает по часовой стрелке, отрицательное —
против. Например, `return { turretTurn: 0.5 };` вращает башню с половиной
максимальной угловой скорости после плавного разгона. `turretTurn: 0` плавно
тормозит вращение. Команду нужно возвращать каждый тик; одновременно задавать
`turretTurn` и `aimDirection` нельзя. Поле доступно в JavaScript и Python.

Готовые команды башни возвращаются в поле `aim`: `bot.scan()` вращает башню,
`bot.aimAt(point)` наводит на мировую точку, `bot.holdAim()` фиксирует угол.
Например, переключение с вращения на сопровождение видимого противника:

```js
function tick(state) {
  return {
    aim: state.enemy ? bot.aimAt(state.enemy.position) : bot.scan()
  };
}
```

В Python сначала выполните `import botarena as bot` и верните
`{"aim": bot.scan()}` либо другую команду. Настройки вращения:
`bot.scan({ speed: 0.5, direction: "counterclockwise" })`; в Python —
`bot.scan({"speed": 0.5, "direction": "counterclockwise"})`.
`speed` должна быть больше 0 и не больше 1; по умолчанию башня вращается
по часовой стрелке. Поля `aim`, `aimDirection`, `turretTurn` взаимоисключающие.
Готовые команды управляют только башней; стрельба задаётся отдельно через `shoot`.

## Режиссёрская камера

Новый реплей открывается в режиме «Кино». Основная съёмка ведётся от третьего лица;
вид из башни появляется только как короткая автоматическая вставка.

В режимах «Кино» и «Разрез» режиссёр иногда показывает короткий вид от лица
наводчика: камера смотрит вдоль ствола и сопровождает выстрел. На короткий бой
приходится максимум одна такая вставка, на бой от 12 секунд — две, с интервалом
не менее шести игровых секунд. В сумме вставки занимают не более 10% игровой
шкалы времени. Ракурс выбирается только при открытом обзоре,
достаточной дистанции и спокойном повороте башни. Вход и выход выполняются склейкой.

Проверки монтажного плана и камеры: `node scripts/validate_gunner.mjs`.

## Экспорт видео

Кнопка «Экспорт видео» записывает реплей с начала в выбранном режиме камеры
и с текущими настройками слоёв, скорости и микшера. В файл попадают 3D-арена,
режиссёрские замедления, POV-вставки, титры, HP и итог боя. Звук берётся прямо
с выхода игрового аудиодвижка; микрофон и запись экрана не используются.

Видео записывается в реальном времени, 1280×720, до 30 кадров/с. Основной формат —
WebM; если браузер поддерживает только MP4, используется он. После записи появляется
ссылка «Скачать видео». Во время экспорта настройки плеера зафиксированы; отмена
или завершение возвращают исходную позицию и состояние воспроизведения. Скрытие
вкладки и выход из плеера отменяют запись и освобождают медиапотоки.

При выключенном звуке экспортируется видео без аудиодорожки. Запись ограничена
пятью минутами и 256 МиБ. Для проверки нужны Vite, сервер, изолированный Chrome
с `--remote-debugging-port=9227`, а также `ffprobe` и `ffmpeg` в PATH:

```sh
node scripts/validate_video.mjs
```

## Звук боя

Звук включён по умолчанию. Под реплеем доступны включение/выключение звука,
общая громкость и раскрываемый микшер: двигатели, выстрелы, попадания/уничтожения,
окружение и музыка. Если браузер блокирует автозапуск, аудио запускается после
первого клика или нажатия клавиши; ожидание не мешает выключить звук заранее.

Все звуки процедурно синтезируются на фронтенде через Web Audio API, без аудиофайлов
и сетевых запросов. Двигатели реагируют на скорость, разгон и повороты, эффекты
следуют событиям реплея, а музыкальный ритм усиливается при перестрелке. Пауза
останавливает аудиотаймер, перемотка очищает старые эффекты, замедление и Chrono X-Ray
меняют высоту и фильтрацию звука. При скрытии вкладки звук приостанавливается.

Для проверки аудио запустите Vite и изолированный Chrome с временным профилем
и параметром `--remote-debugging-port=9227`, откройте `http://127.0.0.1:5173`, затем:

```sh
node scripts/validate_audio.mjs
```

Скрипт проверяет настоящий Web Audio: синтез на нескольких частотах дискретизации,
каналы микшера, паузу, перемотку, замедление, повтор событий и освобождение ресурсов.
