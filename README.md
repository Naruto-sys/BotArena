# BotArena

Учебная платформа для боёв программируемых танков. Напишите стратегию на JavaScript, выберите встроенного противника и запустите дуэль. Сервер C# полностью рассчитает бой, а интерфейс React воспроизведёт его по кадрам.

## Локальный запуск

Нужны .NET SDK 10, Node.js 22.12+ и npm.

Сначала настройте PostgreSQL и нужные OAuth-провайдеры по инструкции ниже. Затем соберите
клиент и запустите сервер:

```sh
npm --prefix frontend ci
npm --prefix frontend run build
dotnet run --project server
```

Откройте [http://127.0.0.1:5050](http://127.0.0.1:5050). Для разработки фронтенда запустите `npm --prefix frontend run dev` в отдельном терминале с работающим сервером и откройте [http://127.0.0.1:5173](http://127.0.0.1:5173).

## PostgreSQL и OAuth

Раздел «Сообщество» хранит пользователей, стратегии, версии и библиотеку манёвров в PostgreSQL. Для локального запуска поднимите базу и укажите настройки авторизации:

```sh
docker compose -f server/compose.postgres.yml up -d
```

Docker Compose создаёт пользователя `botarena` и базу `botarena`, заданную через
`POSTGRES_DB`, только при инициализации нового volume. Скопируйте
`server/appsettings.Local.example.json` в `server/appsettings.Local.json` и укажите
пароль `botarena` для конфигурации из Compose либо параметры своей PostgreSQL.
`appsettings.Local.json` исключён из Git.

Создайте OAuth-приложение Yandex ID, запросите права `login:info` и
`login:avatar`, затем перенесите значения полей ClientID и Client secret приложения
в `Authentication:OAuth:Providers:yandex:ClientId` и `ClientSecret`.
Callback URL в настройках Yandex задайте **точно** как
`http://127.0.0.1:5050/auth/callback`. Открывайте локальное приложение через
`http://127.0.0.1:5050`: `localhost` и `127.0.0.1` не взаимозаменяемы для OAuth
и correlation cookie. В production используйте HTTPS и соответствующий публичный
адрес. Никогда не добавляйте Client secret или реальные пароли в Git.

Для входа через GitHub откройте **Settings → Developer settings → OAuth Apps →
New OAuth App**. Укажите Homepage URL `http://127.0.0.1:5050`, а Authorization
callback URL — **точно** `http://127.0.0.1:5050/auth/github/callback`. После
создания приложения перенесите Client ID и сгенерированный Client secret в
`Authentication:OAuth:Providers:github`. Для production создайте отдельное OAuth-приложение с
публичным HTTPS-адресом. Пользователь, вошедший по локальному логину, может
привязать любой настроенный OAuth-сервис в настройках профиля. Для Google callback
по умолчанию: `http://127.0.0.1:5050/auth/google/callback`.

Провайдеры не зашиты во frontend. Сервер читает любое количество дочерних секций
`Authentication:OAuth:Providers`, регистрирует корректно заполненные OAuth-схемы
и публикует безопасный список через `GET /api/auth/providers`. Client secret,
OAuth endpoints и правила разбора профиля в ответ API не попадают. Полный шаблон
Yandex, GitHub и Google находится в `server/appsettings.json`; чтобы добавить
другой сервис, скопируйте одну секцию и задайте уникальный ключ, callback,
authorization/token/userinfo endpoints, scopes и имена JSON-полей профиля.

Те же настройки можно передать переменными среды:

```text
ConnectionStrings__BotArena=Host=127.0.0.1;Port=5432;Database=botarena;Username=botarena;Password=...
Database__MigrateOnStartup=true
Authentication__OAuth__Providers__github__ClientId=...
Authentication__OAuth__Providers__github__ClientSecret=...
Authentication__OAuth__Providers__google__ClientId=...
Authentication__OAuth__Providers__google__ClientSecret=...
Authentication__OAuth__Providers__custom__DisplayName=Example ID
Authentication__OAuth__Providers__custom__CallbackPath=/auth/custom/callback
Authentication__OAuth__Providers__custom__AuthorizationEndpoint=https://example.com/oauth/authorize
Authentication__OAuth__Providers__custom__TokenEndpoint=https://example.com/oauth/token
Authentication__OAuth__Providers__custom__UserInformationEndpoint=https://example.com/api/user
Authentication__OAuth__Providers__custom__Scopes__0=profile
Authentication__OAuth__Providers__custom__SubjectField=id
```

При `Database:MigrateOnStartup=true` сервер создаёт отсутствующую базу и применяет
миграции EF Core, если роль PostgreSQL имеет право `CREATE DATABASE`. Если права
роли ограничены, создайте базу заранее и выдайте ей права на применение миграций.
После первого OAuth-входа пользователь обязан выбрать уникальный ник. Также можно
зарегистрироваться по локальному логину и паролю; пароль хранится только как
стойкий хэш ASP.NET Core Identity. Имя, фамилию, ник и пароль можно менять в профиле.

Новый пользователь получает 1000 виртуальных кредитов. Кредиты можно получить за победы в дружеских боях на ставку и продажу опубликованных стратегий. Все списания и начисления записываются в журнал операций PostgreSQL; при ничьей или техническом сбое боя ставки возвращаются обоим игрокам.

## Python в редакторе

По умолчанию доступен JavaScript. Чтобы включить Python на macOS или Linux (ARM64 или x86-64), установите среду из корня репозитория. Для установщика нужен Python 3.11+.

```sh
python3 scripts/install_python_runtime.py
BOTARENA_PYTHON_RUNTIME="$PWD/.botarena/python" dotnet run --project server
```

Запускайте сервер от обычного пользователя. Установщик скачивает закреплённые версии CPython WASI и Wasmtime и сверяет SHA-256. После перезапуска выберите **Python** в поле «Язык стратегии». Редактор подставит пример и будет хранить отдельный черновик для каждого языка до перезагрузки страницы.

```python
def tick(state):
    return {"leftTrack": 1, "rightTrack": 1}
```

Поля команды одинаковы в обоих языках. В Python состояние и вложенные объекты приходят как словари, массивы как списки, а скрытый противник обозначен `None`.

## Стратегия

Редактор содержит готовую стратегию. Минимальный бот остаётся на месте и ведёт огонь по видимой цели:

```js
function tick({ self, enemy }) {
  if (!enemy) return {};
  const x = enemy.position.x - self.position.x;
  const y = enemy.position.y - self.position.y;
  const error = Math.atan2(y, x) - self.turretAngle;
  return {
    aimDirection: { x, y },
    shoot: self.canShoot && Math.abs(Math.atan2(Math.sin(error), Math.cos(error))) < 0.05
  };
}
```

`leftTrack` и `rightTrack` задают тягу гусениц в диапазоне от −1 до 1. Можно проще: `driveTo: { x, y }` и `aimAt: { x, y }`, либо хелперы `driveTo(self, point)`, `aimAt(self, point)`, `facing(self, point)`. Пропущенные команды эквивалентны нулевой тяге, сохранению направления башни и отсутствию выстрела. Состояние JavaScript сохраняется между тиками одного матча. `enemy` равен `null`, когда между центрами танков стоит стена.

Для непрерывного вращения башни вместо `aimDirection` используйте `turretTurn`
от −1 до 1: положительное значение вращает по часовой стрелке, отрицательное —
против. Например, `return { turretTurn: 0.5 };` вращает башню с половиной
максимальной угловой скорости после плавного разгона. `turretTurn: 0` плавно
тормозит вращение. Команду нужно возвращать каждый тик; одновременно задавать
`turretTurn` и `aimDirection` нельзя. Поле доступно в JavaScript и Python.

Готовые команды башни возвращаются в поле `aim`: `bot.scan()` вращает башню,
`bot.aimAt(point)` наводит на мировую точку, `bot.holdAim()` фиксирует угол.
Например, переключение с вращения на сопровождение видимого противника:

```js
function tick(state) {
  return {
    aim: state.enemy ? bot.aimAt(state.enemy.position) : bot.scan()
  };
}
```

В Python сначала выполните `import botarena as bot` и верните
`{"aim": bot.scan()}` либо другую команду. Настройки вращения:
`bot.scan({ speed: 0.5, direction: "counterclockwise" })`; в Python —
`bot.scan({"speed": 0.5, "direction": "counterclockwise"})`.
`speed` должна быть больше 0 и не больше 1; по умолчанию башня вращается
по часовой стрелке. Поля `aim`, `aimDirection`, `turretTurn` взаимоисключающие.
Готовые команды управляют только башней; стрельба задаётся отдельно через `shoot`.

## Режиссёрская камера

Новый реплей открывается в режиме «Кино». Основная съёмка ведётся от третьего лица;
вид из башни появляется только как короткая автоматическая вставка.

В режимах «Кино» и «Разрез» режиссёр иногда показывает короткий вид от лица
наводчика: камера смотрит вдоль ствола и сопровождает выстрел. На короткий бой
приходится максимум одна такая вставка, на бой от 12 секунд — две, с интервалом
не менее шести игровых секунд. В сумме вставки занимают не более 10% игровой
шкалы времени. Ракурс выбирается только при открытом обзоре,
достаточной дистанции и спокойном повороте башни. Вход и выход выполняются склейкой.

Проверки монтажного плана и камеры: `node scripts/validate_gunner.mjs`.

## Экспорт видео

Кнопка «Экспорт видео» записывает реплей с начала в выбранном режиме камеры
и с текущими настройками слоёв, скорости и микшера. В файл попадают 3D-арена,
режиссёрские замедления, POV-вставки, титры, HP и итог боя. Звук берётся прямо
с выхода игрового аудиодвижка; микрофон и запись экрана не используются.

Видео записывается в реальном времени, 1280×720, до 30 кадров/с. Основной формат —
WebM; если браузер поддерживает только MP4, используется он. После записи появляется
ссылка «Скачать видео». Во время экспорта настройки плеера зафиксированы; отмена
или завершение возвращают исходную позицию и состояние воспроизведения. Скрытие
вкладки и выход из плеера отменяют запись и освобождают медиапотоки.

При выключенном звуке экспортируется видео без аудиодорожки. Запись ограничена
пятью минутами и 256 МиБ. Для проверки нужны Vite, сервер, изолированный Chrome
с `--remote-debugging-port=9227`, а также `ffprobe` и `ffmpeg` в PATH:

```sh
node scripts/validate_video.mjs
```

## Звук боя

Звук включён по умолчанию. Под реплеем доступны включение/выключение звука,
общая громкость и раскрываемый микшер: двигатели, выстрелы, попадания/уничтожения,
окружение и музыка. Если браузер блокирует автозапуск, аудио запускается после
первого клика или нажатия клавиши; ожидание не мешает выключить звук заранее.

Все звуки процедурно синтезируются на фронтенде через Web Audio API, без аудиофайлов
и сетевых запросов. Двигатели реагируют на скорость, разгон и повороты, эффекты
следуют событиям реплея, а музыкальный ритм усиливается при перестрелке. Пауза
останавливает аудиотаймер, перемотка очищает старые эффекты, замедление и Chrono X-Ray
меняют высоту и фильтрацию звука. При скрытии вкладки звук приостанавливается.

Для проверки аудио запустите Vite и изолированный Chrome с временным профилем
и параметром `--remote-debugging-port=9227`, откройте `http://127.0.0.1:5173`, затем:

```sh
node scripts/validate_audio.mjs
```

Скрипт проверяет настоящий Web Audio: синтез на нескольких частотах дискретизации,
каналы микшера, паузу, перемотку, замедление, повтор событий и освобождение ресурсов.

## Единый интерфейс

- **Главная** — продолжение следующего доступного испытания и переходы к рабочим областям.
- **Обучение** — карта настоящих глав и уровней API. Пройденные уровни отмечаются локально.
- **Арена → PvE** — команды до 4×4, пресеты или собственный код, HP, карта и позиции. Параметры участников свёрнуты над редактором. Для роботов с собственным кодом можно выбрать шасси и загрузить подходящий пример. Шасси передаётся в `customMatch.spawns[].movement`; пропуск поля сохраняет гусеничную модель.
- **Запись боя** — камеры, сворачиваемые анализ, звук и экспорт WebM. Все инструменты используют настоящую серверную запись.
- **Мастерская** — сохранение именованных стратегий JavaScript/Python с шасси, поиск и открытие на Арене. Стратегия заменяет код первого союзника, сохраняя остальную настройку боя. Стратегии, карта и прогресс хранятся только в браузере; между устройствами не синхронизируются.
- **Онлайн-возможности из main** — вход через Яндекс в верхнем меню; PvP-комнаты на Арене; серверные стратегии, манёвры, карты и друзья в «Сообществе» и вкладке «Публикации и каталог» Мастерской. В «Обучении» вкладка «PvE · Прогресс и рейтинг» открывает серверную кампанию. Эти функции используют PostgreSQL; для запуска боёв нужен вход. Локальная мастерская остаётся отдельной вкладкой.

Тексты интерфейса находятся в `frontend/src/text.ts` (новая навигация и экраны — блок `platformText`). Страницы отделены от управления матчем в `PlatformPages.tsx`, библиотека стратегий — в `strategyLibrary.ts`.

Браузерные регрессии проверяют настоящий локальный сервер. Запустите его после сборки, затем:

```sh
cd frontend
npx playwright install chromium
npm run test:ux
```

Другой адрес сервера можно передать через `BOTARENA_URL`. Python-сценарий пропускается, если сервер не настроен на Python WASI. Для авторизованных браузерных сценариев задайте `BOTARENA_STORAGE_STATE` — путь к приватному Playwright storage state (например, внутри игнорируемой `.botarena/`). Без него проверяются гостевой интерфейс, границы авторизации и редактор карты; сценарии расчёта явно пропускаются. HTTP smoke принимает `BOTARENA_COOKIE` и `BOTARENA_URL`, без сессии проверяет публичные API и ответ 401 на запуск боя. Не коммитьте состояние входа или cookies. Тесты используют изолированные браузерные контексты, не затрагивая пользовательские данные.


### Проверки редактора и интерфейса

Недопустимое размещение стены или робота отображается красным как несохранённый
предпросмотр. Роботы автоматически не перемещаются; пока предпросмотр не исправлен
или не отменён, запуск заблокирован. В библиотеке карт такая стена тоже подсвечивается
красным, а сохранение отключается. В браузерное хранилище попадает только принятая карта.

Камера записи по умолчанию — «План». Выбор запоминается на этом устройстве и
сохраняется при пересчёте матча. Если выбранного робота больше нет, включается «План».

`npm --prefix frontend run test:ux` проверяет гостевые матчи и создаёт отдельные
локальные QA-аккаунты для проверки входа, карт, стратегий и PvP. Запускайте проверки
с отдельной тестовой PostgreSQL-базой. Настоящий вход через внешние OAuth-сервисы
в этот набор не входит. Для Python нужен настроенный WASI runtime.

Комнаты: основные поля — название, карта и видимость; приватная комната требует
пароль ещё до создания. Пароли хранятся как хеши и не входят в ответы API.
Приватные комнаты доступны по приглашению, публичный список их не показывает.
Один создатель может иметь одну открытую или рассчитываемую комнату; ограничение
проверяется транзакционно и при одновременных запросах. `/api/rooms/mine` позволяет
вернуться в активную комнату с собственным черновиком. После списания ставок
расчёт завершается и при закрытии вкладки; отмена открытой комнаты прекращает
ожидание второго игрока.

Конструктор сохранённых карт использует те же инструменты, что и Арена.
Кнопка «Играть на карте» переносит карту в локальный матч; карта также доступна
в настройках PvP-комнаты. Тема редактора переключается без потери кода и undo;
арена и предпросмотр используют соответствующую палитру. Учебная цель находится
в 3D-сцене на плоскости арены, поэтому остаётся привязана к карте при смене камеры.
