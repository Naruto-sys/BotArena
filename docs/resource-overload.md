# Перегрузка и вычислительные ресурсы BotArena

Документ описывает перегрузку — самоуничтожение танка при превышении лимита памяти его стратегии. Механика связывает ограниченность бортового компьютера с ограничениями исполнения пользовательского кода.

Базовое свойство: превышение установленного лимита памяти во время матча уничтожает танк. Дополнительные правила результата и взаимодействий приведены как базовая спецификация; численные бюджеты и способ измерения суммарной памяти бота не определены. В текущей реализации есть ограничения ресурсов, но нет отдельной игровой причины уничтожения «Перегрузка».

Связанные документы: [режимы игры](game-modes.md), [вооружение](weapons.md), [предметы](consumables.md), [биомы](biomes.md), [пользовательский API](user-api.md).

## 1. Лимит памяти

Каждая стратегия исполняется с ограниченным бюджетом памяти. Лимит относится к конкретному боту и действует на протяжении всего матча, включая сохранённое между тиками состояние.

Для бюджета различаются три величины:

| Величина | Значение |
| --- | --- |
| Суммарная память среды бота | Память, используемая экземпляром стратегии, включая сохраняемое состояние и временные данные |
| Выделения за вызов | Объём памяти, выделенный во время одного выполнения кода, включая уже ненужные временные объекты |
| Память процесса матча | Общие ресурсы симуляции, сред стратегий, сериализации и реплея внутри рабочего процесса |

Ограничение выделений за вызов не заменяет ограничение суммарной памяти: небольшие добавления в сохранённый список на каждом тике могут накапливаться весь матч. Общий размер процесса также не определяет, какой бот превысил собственный бюджет.

Конкретная метрика фиксируется в правилах исполнения: используемая память среды, выделенная ей память либо другая измеримая величина. Объём живых объектов, размер выделенной кучи и резидентная память процесса не считаются взаимозаменяемыми показателями. Порог перегрузки проверяется по выбранной метрике, а не по длине исходного кода или числу элементов пользовательского массива.

Лимит публикуется до запуска. Попытка выделения памяти сверх бюджета может быть отклонена до фактического получения памяти; для перегрузки достаточно подтверждённого нарушения лимита, занимать лишнюю память сервера не требуется.

## 2. Срабатывание перегрузки

1. Контроль исполнения обнаруживает превышение бюджета конкретного бота.
2. Исполнение его стратегии останавливается. Неполученная или незавершённая команда не применяется.
3. Танк уничтожается с отдельной причиной «Перегрузка памяти».
4. Дальнейшие решения этого экземпляра стратегии не выполняются. Результат матча определяется с учётом его выбытия.

Перегрузка является отказом бортового компьютера. Остаток HP, броня, класс оружия и длительность заряда не предотвращают её. Щит и ремонтный комплект не восстанавливают остановленную стратегию.

В базовой спецификации перегруженный бот выбывает до конца текущего матча, в том числе в режимах с обычными возрождениями. Это отличается от уничтожения снарядом и исключает цикл повторного запуска неисправной стратегии. Новый матч создаёт новую среду и начинает учёт ресурсов заново.

Команда бота на тике перегрузки не исполняется. Порядок обработки остальных команд, привязка события к текущему кадру и разрешение нескольких перегрузок в одном цикле должны быть одинаково определены для всех участников; эти детали пока не зафиксированы. Порядок опроса ботов сам по себе не является правилом выбора победителя.

## 3. Взаимодействия и результат

| Ситуация | Результат базовой спецификации |
| --- | --- |
| Перегрузка одного бота в дуэли | Побеждает исправный противник |
| Подтверждённая перегрузка обоих ботов одного игрового шага | Ничья |
| Перегрузка в командном режиме | Выбывает конкретный бот; остальные союзники продолжают матч |
| У стороны не осталось ботов, способных продолжить матч или обычное возрождение | Сторона проигрывает |
| Перегрузка в испытании или выживании | Попытка завершается неудачей; достигнутый прогресс сохраняется в результате |
| Перегрузка до начала матча, при загрузке кода | Запуск отклоняется с диагностикой; игровое уничтожение не воспроизводится |
| Неподтверждённая причина завершения общего процесса | Сбой платформы, без автоматического обвинения одного из ботов |

В режиме «Каждый за себя» перегрузка выводит участника из текущего матча. Она не даёт очко другому участнику. Влияние досрочного выбытия всех или почти всех участников на завершение матча и итоговые места пока не определено.

При перегрузке носителя флаг падает по обычным правилам уничтожения. Перегруженный танк перестаёт участвовать в контроле зоны. Выпущенные до перегрузки снаряды сохраняются и продолжают подчиняться правилам своего оружия.

Эффект самоуничтожения обозначает причину выбытия. В базовой спецификации он не наносит урон соседним танкам: намеренное выделение памяти не становится дополнительным оружием.

Перегрузка памяти отличается от перегрева оружия. Заряд гаусс-пушки, охлаждающий предмет и свойства биома сами по себе не меняют вычислительный бюджет. Предметы, увеличивающие доступную память, не входят в описанную механику.

## 4. Индикация и диагностика

Перегрузка отображается в реплее как отдельное событие с идентификатором бота, игровым тиком и причиной уничтожения. Визуальный эффект сопровождается текстовой подписью; цвет и анимация не являются единственным обозначением причины.

В отчёте различаются превышение памяти, превышение времени исполнения, ошибка пользовательского кода и сбой платформы. Сообщение об ошибке не сводится к формулировке «танк взорвался».

Диагностика содержит установленный лимит и доступные измерения. Если среда сообщает только факт превышения, точный расход памяти не выдумывается. Пиковое значение и момент последнего измерения указываются только при наличии этих данных.

Показатель текущей загрузки памяти и предварительное предупреждение являются дополнительными вариантами интерфейса. Их наличие, периодичность обновления и пороги не определены. Отсутствие предупреждения не разрешает превысить лимит.

Реплей сохраняет уже принятое решение о перегрузке. Повторное воспроизведение не запускает стратегию и не измеряет ресурсы заново. Повторный расчёт матча не гарантирует совпадение поведения сборщика мусора или расхода памяти.

## 5. Ограничения исполнения

Ограничение памяти дополняется бюджетом вычислений и времени. Бесконечный цикл может практически не выделять память, поэтому одного memory limit недостаточно для ограничения всех ресурсов.

Превышение памяти должно быть подтверждено средой исполнения или внешним контролем конкретного бота. Перехват исключения внутри пользовательского кода не отменяет уже подтверждённую перегрузку. Обработка этой ситуации находится вне управления стратегии.

Самоуничтожение является игровым последствием остановки исполнения. Защита ресурсов действует до формирования реплея и отображения взрыва. Визуальная анимация не задерживает освобождение ресурсов и не даёт стратегии продолжить выполнение.

Память симуляции, очереди и реплея не вычитается из пользовательского бюджета без явного определения правил учёта. Для среды исполнения учитывается её собственная стоимость: одинаковое число байтов для JavaScript и Python не означает одинаковый доступный объём пользовательских данных.

Точные лимиты по языкам, учёт служебных данных, способ измерения сохранённого состояния и частота проверок не установлены. Они являются параметрами исполнения; утверждённого значения в мегабайтах для игровой перегрузки пока нет.

## 6. Текущая реализация

Пользовательский код уже ограничен и не получает полного контроля над ресурсами сервера.

| Уровень | Действующее ограничение | Значение для перегрузки |
| --- | --- | --- |
| JavaScript / Jint | `LimitMemory(4_000_000)` | Ограничивает учитываемые Jint выделения в рамках вызова; не является лимитом всей сохранённой памяти бота за матч |
| Python / Wasmtime | `max-memory-size=67108864` | Ограничивает линейную WASM-память значением 64 МиБ, включая размещённую в ней среду Python; не является пределом всей памяти процесса Wasmtime |
| Рабочий процесс матча | `DOTNET_GCHeapHardLimit=0x8000000` | Ограничивает управляемую кучу .NET значением 128 МиБ; не является индивидуальным бюджетом бота или ограничением всей памяти процесса |
| Время и вычисления | Ограничения вызовов стратегий, число инструкций и дедлайн процесса матча 5 секунд | Дополняют ограничения памяти; это отдельные причины остановки |

Настройки находятся в [JavaScriptBot.cs](../modules/Strategies/JavaScriptBot.cs), [PythonBot.cs](../modules/Strategies/PythonBot.cs) и [MatchWorker.cs](../server/MatchWorker.cs). Семантика учёта выделений Jint определяется [MemoryLimitConstraint версии 4.17.0](https://github.com/sebastienros/jint/blob/v4.17.0/Jint/Constraints/MemoryLimitConstraint.cs) и границами выполнения в [Engine.cs](https://github.com/sebastienros/jint/blob/v4.17.0/Jint/Engine.cs).

В JavaScript распознанное превышение лимита памяти преобразуется в общую ошибку исполнения. Ошибка стратегии на тике приводит к поражению с `result.reason = "BotError"`. В Python сообщение зависит от того, вернула ли гостевая среда ошибку или завершилась без корректного ответа; отдельная надёжная классификация перегрузки отсутствует.

Обе JavaScript-стратегии и симуляция выполняются в одном рабочем процессе .NET. Его общий аварийный предел нельзя использовать для присуждения перегрузки конкретному танку. Python исполняется в дочерней среде Wasmtime.

В действующем контракте нет отдельной причины или события перегрузки, показателя памяти в наблюдении и игрового самоуничтожения по этому правилу. Документ задаёт механику и отличия от существующего поведения; код исполнения и симуляции не изменён.
