# Контекст BotArena

BotArena — учебная браузерная платформа для разработки и сравнения алгоритмов управления танками. Гавриил Купцов ведёт платформу, симуляцию и исполнение стратегий. Карты и режимы, визуализация, дизайн механик и UGC — отдельные направления команды. [Страница проекта в CS Unicorns Wiki](https://cs-uni.ru/index.php?title=BotArena).

## Текущее состояние

Реализованы JavaScript/Python-стратегии, тренировочная арена с командами до 4×4,
уничтожение и захват точки, обучение, PvE-кампания, PvP-комнаты 1×1 с повторными
раундами и 3D-реплеи. Аккаунты, серверный прогресс, публикации стратегий, манёвры,
карты, друзья и виртуальная экономика хранятся в PostgreSQL. Для входа доступны
локальный логин и настраиваемые OAuth-провайдеры.

Актуальные возможности и инструкция сборки находятся в [README](../README.md),
API стратегий — в [user-api.md](user-api.md), игровые режимы — в
[game-modes.md](game-modes.md). Разделы ниже описывают устройство базового движка
и контракт матча; параметры конкретного режима могут отличаться от классической дуэли.
Захват флага, пользовательские режимы и интерактивный пошаговый отладчик остаются
направлениями развития.

## Модули

- `modules/Simulation` содержит физику арены, геометрию столкновений и типы игрового состояния. Проект собирается отдельно и зависит только от .NET.
- `modules/Strategies` содержит контракт `IBotRuntime` и адаптеры JavaScript на Jint и Python на CPython WASI. Адаптер получает наблюдение движка и возвращает команду.
- `server` отвечает за HTTP, очередь, запуск рабочего процесса и каталог противников. Рабочий процесс создаёт стратегии, а `Match.Run` принимает два готовых `IBotRuntime` и выполняет цикл матча.
- `frontend` отвечает за редактор, состояние запроса и воспроизведение реплея.

Другой язык подключается как реализация `IBotRuntime`. Выбор реализации происходит в рабочем процессе. Противник может продолжать использовать JavaScript независимо от языка стратегии игрока.

## Поток матча

1. React отправляет код и ID противника. ASP.NET Core валидирует запрос и ставит матч в общую очередь FIFO. Один рабочий процесс выполняет расчёт, до 16 задач могут ожидать.
2. Рабочий процесс создаёт отдельную среду на каждого бота. Встроенные соперники используют стратегию на C# и обходят стены через доступные углы с запасом под корпус. Язык стратегии игрока выбирается в редакторе. `Match` получает наблюдения с одного и того же тика и собирает обе команды до вызова `Duel.Step`.
3. `Duel` считает разгон, поворот корпуса и башни, столкновения прямоугольников, снаряды, перезарядку и урон. Стены перекрывают видимость и снаряды. Снаряд проверяется вдоль пройденного отрезка.
4. Начальное состояние имеет тик 0. Матч идёт при 20 тиках/с до уничтожения танка или 200 тиков (10 игровых секунд). Если к концу десятой секунды оба танка живы, матч заканчивается ничьей независимо от HP.
5. Сервер возвращает реплей целиком. React интерполирует координаты и углы соседних кадров, отображает события и позволяет ставить запись на паузу, перематывать и менять скорость.

## Несколько роботов

Ядро принимает две или больше уникальных стартовых позиций. Перед шагом оно получает команды всех живых роботов. Столкновения проверяются по соседним клеткам пространственной сетки, а снаряд попадает в первую цель на пути, если её не заслоняет стена. Уничтоженные роботы остаются в кадрах для реплея и исключаются из дальнейшей симуляции. Бой заканчивается, когда остаётся не больше одного участника, или ничьей по лимиту времени. В редакторе доступны дуэль и режим «Каждый за себя» на трёх или четырёх роботов. У каждого участника свой выбор модели и у каждого соперника свой экземпляр встроенной стратегии. Если стратегия ошиблась, робот выбывает с сохранением HP в реплее, а остальные продолжают бой.

## Модели движения

`BotSpawn.Movement` задаёт модель отдельного робота. При запуске без модели движок использует гусеничное управление. Например, чтобы проверить воздушную подушку в локальном сценарии ядра, создайте `Duel` с таким списком стартов:

```csharp
var config = MatchConfig.Classic with
{
    Spawns =
    [
        MatchConfig.Classic.Spawns[0] with { Movement = new HoverMovement(drag: 0.2) },
        MatchConfig.Classic.Spawns[1],
    ],
};
var arena = new Duel(config);
```

`IMovementModel.Propose` принимает позицию робота, угол корпуса, угловую скорость, вектор скорости, команду и длительность тика. Модель вычисляет следующий угол и скорость. Движок проверяет предложенный путь по общей геометрии арены. Если стенка мешает повороту, движок запрашивает движение с прежним углом. Модель должна быть без побочных эффектов, поскольку такой шаг вычисляется повторно. При заблокированном перемещении линейная скорость обнуляется.

У `hover` свои команды `thrust: { x, y }` и `turn`. Тяга действует в координатах арены и ограничена единичной длиной. `turn` задаёт поворот корпуса в диапазоне от −1 до 1. Нулевая тяга позволяет продолжить скольжение с постепенным замедлением. `state.self.velocity` доступна как вектор скорости, а `state.self.movement` содержит ID модели. Команды работают в JavaScript и Python. Проверка Python-адаптера в xUnit запускается с настроенной переменной `BOTARENA_PYTHON_RUNTIME`. В браузере выберите «Воздушная подушка» в поле «Модель движения» и запустите пример. Игрок скользит вверх, поворачивает корпус и тормозит обратной тягой. Модель каждого соперника выбирается отдельно. В реплее след показывает, откуда движется робот. Черновики хранятся отдельно для каждой пары модели и языка до перезагрузки страницы.

Две другие модели используют тот же контракт:

- `wheeled` принимает `throttle` и `turn` от −1 до 1. Поворот зависит от скорости, а при заднем ходе машина описывает дугу в другую сторону.
- `omni` принимает `thrust` и `turn`. Вектор задаёт целевую скорость, поэтому нулевая команда активно тормозит. Корпус можно поворачивать независимо.

Чтобы добавить свою модель:

1. Реализуйте `IMovementModel` в `modules/Simulation` или в отдельном проекте со ссылкой на этот модуль. Присвойте модели уникальный `Id`. Реализуйте `Propose` так, чтобы для одинаковых аргументов результат был одинаковым, а при `canRotate: false` угол оставался прежним.
2. Назначьте модель в `BotSpawn.Movement` и проверьте движение и реакцию на стены через `Duel.Step`. Поворот и скорость передаются между тиками в `BotMotion`. Позиция робота доступна модели для расчёта эффектов, зависящих от места на карте.
3. Чтобы выбрать модель из браузера, добавьте её ID и фабрику в `server/MovementCatalog.cs`. Добавьте вариант, пример и подсказку в редакторе. В реплее ID модели приходит в `bot.movement`, а скорость в `bot.velocity`.
4. Если нужны новые поля команды, обновите `BotAction` и проверку значений в адаптерах JavaScript и Python. Если модель требует отскока или передачи импульса, меняйте правило контакта в арене. Модель движения задаёт свободный ход, а столкновения обрабатывает движок.

## Контракт стратегии

Целевой пользовательский API с низкоуровневым и высокоуровневым управлением,
а также спецификация навигации описаны в [user-api.md](user-api.md).
В документе отдельно отмечены существующие возможности и планируемые расширения.

Координаты отсчитываются от левого верхнего угла, X вправо, Y вниз. Углы в радианах, положительное направление по часовой стрелке. `state` содержит `tick`, `self`, `enemy`, `bullets` и `arena`. В `enemies` перечислены видимые живые противники, а `enemy` содержит ближайшего из них или `null`. Пули видны по всей карте. У бота есть `id`, `position`, `bodyAngle`, `turretAngle`, `speed`, `hp`, `maxHp`, `reloadingTime` (секунды) и `canShoot`. Стены заданы верхним левым углом и размером.

Синхронная `tick(state)` возвращает объект команды. Можно писать низкоуровнево: `leftTrack`, `rightTrack`, `aimDirection: { x, y }` и `shoot`. Можно верхнеуровнево: `driveTo: { x, y }` и `aimAt: { x, y }` — рантайм сам переведёт их в гусеницы и прицел, если низкоуровневые поля не заданы. В среде стратегии доступны хелперы `driveTo`, `aimAt`, `facing`, `distance`, `reached` (в Python также `drive_to` / `aim_at`). Для отладки работают `console.log` / `log` (и `print` в Python); строки попадают в `logs` ответа матча и панель «Отладка». Поля опциональны. Вектор `{ x: 0, y: 0 }` сохраняет угол башни. Команды гусениц ограничиваются диапазоном от −1 до 1. Неконечные числа и неверные типы вызывают ошибку стратегии. Угловые скорости корпуса и башни ограничены и плавно приближаются к заданным. Выстрел идёт по фактическому углу башни в текущем кадре.

Вместо `aimDirection` можно передать `turretTurn` — долю максимальной угловой
скорости башни от −1 до 1. Положительное значение вращает по часовой стрелке,
отрицательное — против; `0` плавно тормозит вращение. Значения за пределами
диапазона ограничиваются. Оба поля одновременно недопустимы. Отсутствие обоих
полей сохраняет текущий угол; команду вращения нужно повторять каждый тик.

Для готового управления башней доступны `aim: bot.scan(options?)`,
`aim: bot.aimAt(point)` и `aim: bot.holdAim()`. В Python библиотека подключается
через `import botarena as bot`. `scan` вращает башню с долей максимальной скорости
`speed` (по умолчанию `0.5`) в направлении `clockwise` или `counterclockwise`.
Поле `aim` нельзя сочетать с `aimDirection` или `turretTurn`. Эти функции не
добавляют автоматический выстрел или упреждение.

## HTTP

- `GET /api/opponents` возвращает `[{ id, name, description }]`.
- `GET /api/campaign` возвращает кампании `[{ id, order, name, summary, available, levelCount, levels }]`. В `levels` — уровни выбранной кампании: `{ id, order, name, summary, objective, hint, arena, marker?, spawns, starter }`. `spawns` и `arena` нужны для превью поля до старта матча.
- `GET /api/strategy-languages` возвращает список установленных языков.
- `POST /api/matches` принимает JSON для Match Lab `{ botCode, language?, movement?, opponents? }`, кампании `{ botCode, language?, campaignLevelId?, botCodes? }` или кастомного матча `{ language?, customMatch }`. При отсутствии `language` используется JavaScript. `movement` задаёт модель игрока; доступны `tracked` (по умолчанию), `hover`, `wheeled` и `omni`. Массив `opponents` содержит от одного до трёх записей `{ id, movement? }`; поле `opponentId` по-прежнему запускает дуэль с гусеничным противником. Запрос возвращает `{ replay, error, logs }`. Реплей содержит `tickRate`, `arena`, `frames`, `result`, `behaviorSamples` и опциональный `marker` для целей «доехать до точки». `error` равен `null` либо содержит `{ botId, tick, message }`. `logs` — массив `{ tick, message }` из `console.log` / `log` стратегии игрока. Для целей кампании `result.reason` может быть `ObjectiveComplete`.
- Ошибка загрузки стратегии возвращает HTTP 422 с `{ error: string }`. При ошибке на тике возвращается HTTP 200 с реплеем и ошибкой бота. Результат получает `reason = "BotError"`, если выбытие завершило матч. В дуэли тик ошибки становится последним кадром. В групповом бою остальные продолжают матч, а в `error` сохраняется первая ошибка.
- Интерфейс запускает расчёт через `POST /api/match-jobs` и получает HTTP 202 с ID. `GET /api/match-jobs/{id}` возвращает статус `queued`, `running` или `completed`. Для ожидающей задачи `position: 1` означает первую позицию среди ожидающих. Готовые результаты хранятся до пяти минут, максимум 32 результата.
- Невалидные параметры дают HTTP 400, заполненная очередь — 429. Сбой или истечение срока рабочего процесса даёт 422 с сообщением.

## Источники и решения

[Первый черновик MVP](https://docs.google.com/document/d/1hnUugPaCYpZwnkgOa9hRNtzfW_xCLBFmPvQUfq1d-Oo/edit) описывает общий цикл, REST и JS/Jint. Для полей и модели движения приоритет отдан уточняющему контракту v0.1 и его двум комментариям о прямоугольных границах. В нём таблица действий расходится с примерами и общими соглашениями. Принят интерфейс гусениц из примеров и отдельный `bodyAngle` из описания состояний и рендера. Для воспроизведения используется готовый JSON. Движок не использует случайность, а пользовательский JavaScript может использовать время или случайные числа, поэтому повторный расчёт не обещает тот же результат.

Сервер слушает loopback. Jint работает без CLR-доступа и динамической компиляции строк, с лимитами инструкций, глубины вызовов, памяти и времени. Рабочий процесс имеет ограничение управляемой кучи и принудительный дедлайн расчёта 5 секунд реального времени. Для публичного исполнения чужого кода нужны отдельные права процесса и ограничения ресурсов на уровне ОС. [Модель угроз Jint](https://sebastienros.github.io/jint/guide/untrusted-code).

Python запускается в Wasmtime. Гостевой процесс получает копию стандартной библиотеки в каталоге только для чтения и обменивается JSON через stdin и stdout. Ему не передаются сеть и переменные среды хоста. WASM-память ограничена 64 МиБ, на запуск выделено до 2 секунд, на один вызов `tick` до 150 мс. Общий дедлайн расчёта остаётся 5 секунд. [CPython WASI](https://github.com/python/cpython/tree/main/Platforms/WASI). [Wasmtime](https://docs.wasmtime.dev/).
