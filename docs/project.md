# Контекст BotArena

BotArena — учебная браузерная платформа для разработки и сравнения алгоритмов управления танками. Гавриил Купцов ведёт платформу, симуляцию и исполнение стратегий. Карты и режимы, визуализация, дизайн механик и UGC — отдельные направления команды. [Страница проекта в CS Unicorns Wiki](https://cs-uni.ru/index.php?title=BotArena).

Первый этап — локальная дуэль 1×1 на карте с укрытиями. Пользователь редактирует JavaScript или Python, выбирает одного из двух встроенных противников, запускает расчёт и просматривает реплей. Командные матчи, захват флага, генерация карт, выбор оружия в интерфейсе, обмен стратегиями и отладчик относятся к дальнейшим этапам. В симуляции уже есть логика обычной пушки, миномёта с уроном по площади и гаусс-пушки; класс задаётся в конфигурации танка. У локального MVP нет аккаунтов и базы данных.

## Модули

- `modules/Simulation` содержит физику дуэли, геометрию столкновений и типы игрового состояния. Проект собирается отдельно и зависит только от .NET.
- `modules/Strategies` содержит контракт `IBotRuntime` и адаптеры JavaScript на Jint и Python на CPython WASI. Адаптер получает наблюдение движка и возвращает команду.
- `server` отвечает за HTTP, очередь, запуск рабочего процесса и каталог противников. Рабочий процесс создаёт стратегии, а `Match.Run` принимает два готовых `IBotRuntime` и выполняет цикл матча.
- `frontend` отвечает за редактор, состояние запроса и воспроизведение реплея.

Другой язык подключается как реализация `IBotRuntime`. Выбор реализации происходит в рабочем процессе. Противник может продолжать использовать JavaScript независимо от языка стратегии игрока.

## Поток матча

1. React отправляет код и ID противника. ASP.NET Core валидирует запрос и ставит матч в общую очередь FIFO. Один рабочий процесс выполняет расчёт, до 16 задач могут ожидать.
2. Рабочий процесс создаёт отдельную среду на каждого бота. Встроенные соперники используют Jint, язык стратегии игрока выбирается в редакторе. `Match` получает наблюдения с одного и того же тика и собирает обе команды до вызова `Duel.Step`.
3. `Duel` считает разгон, поворот корпуса и башни, столкновения прямоугольников, снаряды, перезарядку и урон. Стены перекрывают видимость и обычные снаряды, которые проверяются вдоль пройденного отрезка. Миномётные снаряды проходят поверх стен и при падении наносят урон по площади. Гаусс рассчитывает мгновенный луч с остановкой на первой стене или танке; заряд восстанавливается между выстрелами. [Характеристики и конфигурация оружия](weapons.md#31-характеристики-реализации).
4. Начальное состояние имеет тик 0. Матч идёт при 20 тиках/с до уничтожения танка или 200 тиков (10 игровых секунд). Если к концу десятой секунды оба танка живы, матч заканчивается ничьей независимо от HP.
5. Сервер возвращает реплей целиком. React интерполирует координаты и углы соседних кадров, отображает события и позволяет ставить запись на паузу, перематывать и менять скорость.

Сервер использует `MatchConfig.Biomes`: прежние размеры и стены карты Classic
с клетками песка, снега, льда и тумана. Поверхность влияет на движение,
туман — на наблюдение. Коэффициенты и [таблица сравнения](biomes.md#8-сравнение-параметров)
опубликованы в `arena.terrainRules`. `MatchConfig.Classic` остаётся однородной картой.
На карте Biomes также включены случайно появляющиеся [расходники](consumables.md).
Каждый матч получает новое зерно генератора; реплей сохраняет `randomSeed`.
Подбор автоматический, применение из запаса — через `useItem`.

## Контракт стратегии

Целевой пользовательский API с низкоуровневым и высокоуровневым управлением,
а также спецификация навигации описаны в [user-api.md](user-api.md).
В документе отдельно отмечены существующие возможности и планируемые расширения.

Координаты отсчитываются от левого верхнего угла, X вправо, Y вниз. Углы в радианах, положительное направление по часовой стрелке. `state` содержит `tick`, `self`, `enemy`, `bullets` и `arena`. Противник за стеной или за пределами обзора через туман скрыт (`enemy: null`). Пули видны по всей карте. У бота есть `id`, `position`, `bodyAngle`, `turretAngle`, `speed`, `hp`, `maxHp`, `reloadingTime` (секунды), `canShoot`, `weapon` (`Cannon`, `Mortar` или `Gauss`), `chargeStage`, `chargeProgress`, `surface` и `inFog`. Арена содержит стены, размер и список клеток, параметры окружения.

Синхронная `tick(state)` возвращает объект с `leftTrack`, `rightTrack`, `aimDirection: { x, y }` и `shoot`. Поля опциональны. Вектор `{ x: 0, y: 0 }` сохраняет угол башни. Команды гусениц ограничиваются диапазоном от −1 до 1. Неконечные числа и неверные типы вызывают ошибку стратегии. Угловые скорости корпуса и башни ограничены и плавно приближаются к заданным. Выстрел обычной пушки и гаусса идёт по фактическому углу башни в текущем кадре. Для выстрела миномёта дополнительно передаётся `targetPoint: { x, y }` внутри арены; направление башни не ограничивает выбор точки.

Вместо `aimDirection` можно передать `turretTurn` — долю максимальной угловой
скорости башни от −1 до 1. Положительное значение вращает по часовой стрелке,
отрицательное — против; `0` плавно тормозит вращение. Значения за пределами
диапазона ограничиваются. Оба поля одновременно недопустимы. Отсутствие обоих
полей сохраняет текущий угол; команду вращения нужно повторять каждый тик.

Для готового управления башней доступны `aim: bot.scan(options?)`,
`aim: bot.aimAt(point)` и `aim: bot.holdAim()`. В Python библиотека подключается
через `import botarena as bot`. `scan` вращает башню с долей максимальной скорости
`speed` (по умолчанию `0.5`) в направлении `clockwise` или `counterclockwise`.
Поле `aim` нельзя сочетать с `aimDirection` или `turretTurn`. Эти функции не
добавляют автоматический выстрел или упреждение.

## HTTP

- `GET /api/opponents` возвращает `[{ id, name, description }]`.
- `GET /api/strategy-languages` возвращает список установленных языков.
- `POST /api/matches` принимает JSON `{ botCode, opponentId, language? }`. При отсутствии `language` используется JavaScript. Запрос возвращает `{ replay, error }`. Реплей содержит `tickRate`, `arena`, `frames`, `result`, `randomSeed`; кадры включают предметы и дым. `error` равен `null` либо содержит `{ botId, tick, message }`.
- Ошибка загрузки стратегии возвращает HTTP 422 с `{ error: string }`. При ошибке на тике возвращается HTTP 200 с уже рассчитанными кадрами, `result.reason = "BotError"` и ошибкой бота. Тик ошибки остаётся последним кадром, победа присуждается другой стороне.
- Интерфейс запускает расчёт через `POST /api/match-jobs` и получает HTTP 202 с ID. `GET /api/match-jobs/{id}` возвращает статус `queued`, `running` или `completed`. Для ожидающей задачи `position: 1` означает первую позицию среди ожидающих. Готовые результаты хранятся до пяти минут, максимум 32 результата.
- Невалидные параметры дают HTTP 400, заполненная очередь — 429. Сбой или истечение срока рабочего процесса даёт 422 с сообщением.

## Источники и решения

[Первый черновик MVP](https://docs.google.com/document/d/1hnUugPaCYpZwnkgOa9hRNtzfW_xCLBFmPvQUfq1d-Oo/edit) описывает общий цикл, REST и JS/Jint. Для полей и модели движения приоритет отдан уточняющему контракту v0.1 и его двум комментариям о прямоугольных границах. В нём таблица действий расходится с примерами и общими соглашениями. Принят интерфейс гусениц из примеров и отдельный `bodyAngle` из описания состояний и рендера. Для воспроизведения используется готовый JSON. Появление предметов и равный спор при подборе используют генератор с `MatchConfig.RandomSeed`; при одинаковых правилах, зерне и командах результат воспроизводим в одной версии движка. Время и случайность внутри пользовательского кода по-прежнему могут изменить повторный расчёт.

Сервер слушает loopback. Jint работает без CLR-доступа и динамической компиляции строк, с лимитами инструкций, глубины вызовов, памяти и времени. Рабочий процесс имеет ограничение управляемой кучи и принудительный дедлайн расчёта 5 секунд реального времени. Для публичного исполнения чужого кода нужны отдельные права процесса и ограничения ресурсов на уровне ОС. [Модель угроз Jint](https://sebastienros.github.io/jint/guide/untrusted-code).

Python запускается в Wasmtime. Гостевой процесс получает копию стандартной библиотеки в каталоге только для чтения и обменивается JSON через stdin и stdout. Ему не передаются сеть и переменные среды хоста. WASM-память ограничена 64 МиБ, на запуск выделено до 2 секунд, на один вызов `tick` до 150 мс. Общий дедлайн расчёта остаётся 5 секунд. [CPython WASI](https://github.com/python/cpython/tree/main/Platforms/WASI). [Wasmtime](https://docs.wasmtime.dev/).
