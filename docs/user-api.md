# Пользовательский API стратегий BotArena

Статус: проект целевого API v1. Документ описывает интерфейс стратегии игрока;
HTTP-интерфейс платформы описан в [контексте проекта](project.md#http).

После синхронизации с `origin/main` движок поддерживает команды, несколько
противников, шасси `tracked`, `hover`, `wheeled`, `omni` и сжимающуюся зону.
Наблюдение также содержит `enemies` (видимые противники, без союзников)
и `safeZone`; `enemy` остаётся ближайшим видимым противником. `allies` содержит
состояния союзников. В «Царе горы» противники видны всей команде, если их
наблюдает хотя бы один живой союзник; в остальных режимах остаётся личная
видимость. У танка есть
`teamId`, `movement`, `velocity`, `forfeited`. Запасы скрыты во всех элементах
`enemies`, а не только у ближайшего противника. Стандартный лимит теперь
1000 тиков (50 с при 20 тиках/с), конкретные уровни задают свои ограничения.
Для колёсного шасси доступны `throttle`/`turn`, для hover/omni — `thrust`/`turn`.
Эти каналы независимы от `turretTurn`, `aim`, оружия и `useItem`.

**Уже реализованы:** `tick(state)`, наблюдение из раздела 2.1, низкоуровневый
ответ из раздела 3, включая `turretTurn`, сохранение памяти стратегии между
тиками, физика столкновений, поле `aim` и функции `bot.scan`, `bot.aimAt`,
`bot.holdAim` для JavaScript и Python; логика миномёта с уроном по площади,
гаусс-пушка с мгновенным лучом и автоматическим зарядом, поля `weapon`,
`chargeStage`, `chargeProgress` и команда `targetPoint` из разделов 3.1–3.2.
Оружие выбирается в лаборатории для каждого танка; HTTP-поле
`customMatch.spawns[].weapon` принимает `Cannon`, `Mortar`, `Gauss`.
Отсутствующее поле означает `Cannon`. Выбор не меняет пользовательский код:
для миномёта нужно передавать `targetPoint`; встроенные пресеты и примеры
учитывают это требование.
Реализованы клетки песка, снега и льда, туман, поля `surface` и `inFog`,
публичная карта `arena.cells` и коэффициенты `arena.terrainRules`.
Реализованы случайное появление и подбор расходников, запас,
`useItem`, щит, ремонт, ускорение, охлаждение и дым (раздел 3.3).
**Предстоит реализовать:** поля наблюдения из раздела 2.2, команды `move` и
`fire`, навигация, её статусы, геометрические запросы, расчёт упреждения и
условная стрельба. Примеры с этими возможностями пока не запускаются в редакторе.

## 1. Два уровня управления

| Уровень | Что выбирает игрок | Что выполняет платформа |
| --- | --- | --- |
| Высокоуровневый | Точку назначения, маршрут, направление прицеливания | Поиск пути, руление, торможение, наведение |
| Низкоуровневый | Тягу каждой гусеницы, вектор башни, запрос выстрела | Только физику, ограничения механизмов и столкновения |

Уровни можно сочетать по независимым каналам: например, пользоваться навигацией,
но самостоятельно рассчитывать упреждение, либо управлять гусеницами и наводить
башню через `aimAt`. Навигация не выбирает боевую цель, укрытие или момент выстрела.
Все команды подчиняются одним ограничениям двигателя; высокий уровень не даёт
преимущества в скорости, видимости или точности оружия.

### Цикл стратегии

```js
function tick(state) {
  return { /* команды на следующий шаг симуляции */ };
}
```

В Python точка входа — `def tick(state)`, результат — словарь. Состояние и
вложенные объекты передаются словарями и списками. JavaScript использует `null`,
Python — `None`. Стратегия синхронная; асинхронный результат не поддерживается.
Глобальные переменные сохраняются внутри одного матча и сбрасываются перед новым.

Оба бота получают наблюдения одного тика до применения любой из их команд.
Команда действует один шаг. Для продолжения движения её нужно возвращать каждый
тик. Изменения входного объекта не изменяют мир. Внешнее время и случайность
стратегии могут нарушить воспроизводимость повторного расчёта.

## 2. Наблюдение `state`

Координаты отсчитываются от левого верхнего угла: X вправо, Y вниз. Углы —
радианы, положительный поворот по часовой стрелке. `Point` и `Vector` имеют
поля `{ x, y }`; у точки это мировые координаты, у вектора — направление.
Расстояния указаны в единицах арены, время — в игровых секундах.

### 2.1. Существующие поля

| Поле | Содержимое |
| --- | --- |
| `tick` | Номер текущего тика, начиная с 0 |
| `self` | Состояние своего танка |
| `enemy` | Состояние видимого противника или `null` |
| `bullets` | Все снаряды на карте, включая находящиеся за стеной |
| `arena` | `{ width, height, walls, cellSize, cells, terrainRules }`; стены: `{ x, y, width, height }` |
| `allies` | Состояния союзников, включая уничтоженных или исключённых |
| `kingOfHill` | `null` в других режимах; в «Царе горы»: `{ zone: { center, radius }, scoreLimit, controllingTeamId, contested, scores: [{ teamId, score }], respawns: [{ botId, secondsRemaining, waitingForSpace }] }` |
| `deathmatch` | `null` в других режимах; в Deathmatch: `{ scoreLimit, standings: [{ botId, score, kills, deaths, alive, forfeited, respawnSecondsRemaining, waitingForSpace }] }`. Таблица публична, позиции скрытых танков и будущая точка возрождения в неё не входят |
| `items` | Видимые предметы `{id, type, position}` |
| `smokeClouds` | Видимые облака `{id, ownerBotId, position, radius, expiresAtTick}` |
| `consumableRules` | Правила появления, подбора, вместимости и эффектов |

Танк: `id`, `position`, `bodyAngle`, `turretAngle`, `speed`, `hp`, `maxHp`,
`reloadingTime`, `canShoot`, `weapon` (`"Cannon"`, `"Mortar"` или `"Gauss"`),
`chargeStage`, `chargeProgress`, `surface`, `inFog`, `inventory`, `activeEffects`,
`shieldHp`. `speed` — продольная скорость со знаком, а не вектор;
отрицательное значение означает задний ход. Противник скрывается, когда стена
перекрывает отрезок между центрами танков, либо туман на этом отрезке ограничивает
обзор и расстояние превышает `arena.terrainRules.fogVisibilityRange` (по умолчанию 4),
либо дым на линии зрения ограничивает обзор до 2 ед. по умолчанию.
Сохранённые игроком наблюдения не
обновляются после потери видимости.

Для гаусса `chargeStage` равен `"Charging"` или `"Ready"`, а `chargeProgress`
содержит долю восстановленного заряда от 0 до 1. В начале матча гаусс готов:
`chargeStage: "Ready"`, `chargeProgress: 1`. Зарядка совмещена с перезарядкой;
`canShoot` становится `true` при полном заряде. У обычной пушки и миномёта
`chargeStage: "None"`, `chargeProgress: 0`. Состояние заряда доступно также
у видимого противника; скрытый противник по-прежнему не передаётся.

`surface` — `"Ground"`, `"Sand"`, `"Snow"` или `"Ice"`, `inFog` — логическое
значение. Клетка выбирается по центру танка. `arena.cellSize` задаёт её размер,
`arena.cells` — разреженный массив `{x, y, surface, fog}` с целочисленными
индексами; незаданные клетки — грунт без тумана. Карта публична целиком.
`arena.terrainRules` содержит `sand`, `snow`, `ice` с множителями
`speedMultiplier`, `accelerationMultiplier`, `decelerationMultiplier`,
`turnMultiplier` и общий `fogVisibilityRange`.
Поверхность в наблюдении соответствует текущей позиции; её коэффициенты
применяются в начале следующего шага. Туман может накладываться на любую
поверхность, сохраняет видимость всех снарядов и не ограничивает оружие.
Полные [правила и таблица параметров](biomes.md#8-сравнение-параметров).

Снаряд: `id`, `ownerBotId`, `position`, `direction`, `weapon`, `targetPoint`,
`launchTick`, `impactTick`. Для миномёта `position` — проекция на карту,
`direction` — направление к выбранной точке при запуске, `targetPoint` —
зафиксированная цель, `launchTick` — тик запуска, `impactTick` — тик падения.
Эти данные доступны для всех миномётных снарядов по всей карте.
Для обычной пули `targetPoint` и `impactTick` равны `null`, а `launchTick`
также содержит тик запуска. Полёт миномёта не добавляет наблюдений скрытых танков.
Гаусс не создаёт летящих снарядов в `bullets`: попадание рассчитывается
на одном шаге симуляции, след луча передаётся только в событиях реплея.

### 2.2. Дополнения для целевого API

| Поле | Назначение |
| --- | --- |
| `dt` | Длительность шага симуляции в секундах |
| `self.bodyTurnRate`, `self.turretTurnRate` | Текущие угловые скорости в радианах/с для собственных контроллеров |
| `rules` | Параметры физики и оружия данного матча |
| `navigation` | Результат выполнения собственной команды навигации к текущему наблюдению |

`rules` публикует параметры `MatchConfig`: `maxForwardSpeed`, `maxReverseSpeed`,
`acceleration`, `deceleration`, `maxTurnSpeed`, `turnResponseSeconds`,
`maxTurretTurnSpeed`, `botLength`, `botWidth`, `bulletLength`, `bulletWidth`,
`bulletSpeed`, `bulletDamage`, `shotCooldownTicks`, а также `tickRate`, `maxTicks`.
Размеры корпуса позволяют писать свою навигацию без констант из исходников.
Внутренняя память навигации другого бота не раскрывается.

## 3. Низкоуровневые команды: работают сейчас

```js
return {
  leftTrack: 1,
  rightTrack: 0.5,
  aimDirection: { x: 1, y: 0 },
  shoot: false
};
```

| Поле | Значение по умолчанию | Семантика |
| --- | --- | --- |
| `leftTrack` | `0` | Тяга левой гусеницы, ограничивается диапазоном `[-1, 1]` |
| `rightTrack` | `0` | Тяга правой гусеницы, ограничивается диапазоном `[-1, 1]` |
| `aimDirection` | `{ x: 0, y: 0 }` | Направление башни в мировых осях; нулевой вектор сохраняет угол |
| `turretTurn` | Не задано | Целевая угловая скорость башни как доля максимума, ограничивается `[-1, 1]`; альтернатива `aimDirection` |
| `shoot` | `false` | Попытка выстрелить при готовом оружии |
| `useItem` | Не задано | Применить один предмет из запаса: `Repair`, `Shield`, `SpeedBoost`, `Coolant`, `Smoke` |

Среднее тяги определяет целевую продольную скорость, разница — целевую скорость
поворота. `leftTrack > rightTrack` поворачивает корпус по часовой стрелке.
Торможение, разгон и повороты требуют времени. Танк не может двигаться боком.
Нулевая тяга тормозит, но не обнуляет скорость мгновенно; поворот корпуса также
затухает по правилам физики. Башня управляется независимо от корпуса.

Для прямого вращения башни верните `turretTurn`: положительное значение
вращает по часовой стрелке, отрицательное — против. Например, `0.5` задаёт
половину максимальной угловой скорости. Механизм плавно приближается к ней;
вращение непрерывно проходит границу углов `±π` и не зависит от поворота корпуса.
`turretTurn: 0` плавно гасит вращение, поэтому башня ещё некоторое время
доворачивается. Это отличается от отсутствия обоих полей башни или нулевого
`aimDirection`: для совместимости они сразу фиксируют текущий мировой угол.
Каждую команду вращения нужно повторять на каждом тике.

```js
function tick(state) {
  return { leftTrack: 1, rightTrack: 1, turretTurn: 0.5 };
}
```

```python
def tick(state):
    return {"leftTrack": 1, "rightTrack": 1, "turretTurn": 0.5}
```

Одновременные `turretTurn` и `aimDirection` — ошибка стратегии, в том числе
при нулевых значениях. `turretTurn` должен быть конечным числом: `null`/`None`,
логические значения и строки не допускаются. Значения вне `[-1, 1]`
ограничиваются, как тяга гусениц. На следующем тике можно переключиться с
вращения на `aimDirection`, механизм использует накопленную скорость поворота.

Выстрел обычной пушки направлен по фактическому углу башни после её поворота на этом шаге.
`shoot: true` не ожидает точного наведения и не сохраняет отложенный выстрел.
Если возвращать его каждый тик, танк стреляет по мере перезарядки.

Результат `tick` должен быть объектом/словарём. Числа должны быть конечными,
`shoot` — логическим значением. В `aimDirection`, если оно передано, обязательны
обе числовые координаты. Ошибка стратегии завершает матч её поражением;
обычное столкновение со стеной ошибкой стратегии не является.

### 3.1. Выстрел миномёта

Класс оружия выбирается в конфигурации симуляции до создания танка. По умолчанию
используется обычная пушка; для миномёта `self.weapon === "Mortar"`.
Миномёт принимает мировую точку атаки независимо от направления башни:

```js
function tick(state) {
  if (state.self.weapon !== "Mortar" || !state.enemy) return {};
  return { shoot: true, targetPoint: state.enemy.position };
}
```

В Python команда имеет тот же вид:
`{"shoot": True, "targetPoint": {"x": 14, "y": 5}}`.
Можно стрелять и в точку, где враг сейчас не виден: видимость не проверяется
для разрешения атаки и не расширяется после запуска.

`targetPoint` содержит обе конечные числовые координаты внутри арены
(`0 <= x <= width`, `0 <= y <= height`). Поле доступно только миномёту;
`null`/`None`, неверный тип или точка вне арены приводят к ошибке стратегии.
Для `shoot: true` точка обязательна, в том числе во время перезарядки.
Без запроса выстрела её можно не передавать. Одна точка без `shoot: true`
не запускает снаряд и не сохраняет цель для будущих команд.

У готового миномёта запускается снаряд с фиксированной точкой падения.
Время полёта определяется расстоянием от позиции танка после движения
на текущем шаге; значения приведены в [характеристиках оружия](weapons.md#31-характеристики-реализации).
При падении проверяется пересечение круга взрыва с текущим повёрнутым корпусом
противника. По умолчанию радиус равен 1,25 ед., урон — 35 HP по всей площади;
стены не блокируют взрыв. Изменение команды или позиции
стрелявшего танка не меняет летящий снаряд. Запрос во время перезарядки
игнорируется без очереди отложенных выстрелов, как у обычной пушки.
Поля `aim`, `aimDirection`, `turretTurn` продолжают управлять только башней
и не изменяют `targetPoint`.

### 3.2. Выстрел гаусс-пушки

Для `self.weapon === "Gauss"` используются обычные команды наведения и `shoot`;
`targetPoint` доступна только миномёту. Пример для JS:

```js
function tick(state) {
  if (!state.enemy) return {};
  const x = state.enemy.position.x - state.self.position.x;
  const y = state.enemy.position.y - state.self.position.y;
  const error = Math.atan2(y, x) - state.self.turretAngle;
  return {
    aim: bot.aimAt(state.enemy.position),
    shoot: state.self.canShoot && Math.abs(Math.atan2(Math.sin(error), Math.cos(error))) < 0.03
  };
}
```

В Python те же данные доступны в `state["self"]`; команда выстрела —
`{"shoot": True}`, вместе с любым допустимым способом наведения.
Гаусс наносит 60 HP в тик выстрела вдоль фактического угла башни после поворота
на текущем шаге. Луч нулевой толщины доходит до первого танка, стены или границы
арены. Стены останавливают луч; пробития и автоматического наведения нет.
Выстрел по текущему углу может промахнуться, даже если передано новое `aim`.

После любого выстрела, включая промах, заряд восстанавливается автоматически
50 тиков (2,5 с при 20 тиках/с). Полный заряд удерживается до нового запроса;
потеря цели не сбрасывает заряд и не вызывает выстрел. Движение и повороты
работают как обычно. `shoot: true` во время зарядки не создаёт очередь.
При непрерывном запросе выстрелы происходят на шагах 1, 51, 101 и далее,
если матч продолжается. Оба бота успевают применить команду одного тика до
подведения итога, поэтому одновременные смертельные попадания дают ничью.

### 3.3. Расходники

`self.inventory` содержит до двух строковых типов предметов. Подбор
автоматический в радиусе 0,65 ед. от центра, через стены недоступен.
Подобранный предмет появляется в следующем наблюдении. `self.activeEffects`
содержит `{type, expiresAtTick}`, `self.shieldHp` — оставшуюся защиту.
`enemy.inventory` всегда пуст, даже у видимого противника. Поле `inFog`
относится только к клеткам тумана; дым представлен в `smokeClouds`.

```js
function tick(state) {
  return state.self.hp < 80 && state.self.inventory.includes("Repair")
    ? { useItem: "Repair" }
    : {};
}
```

В Python: `return {"useItem": "Repair"}`. Все пять имён и ключи одинаковы
в двух языках. Неизвестное имя, неверный регистр, `null`/`None` или значение
нестрокового типа — ошибка стратегии. Если такого предмета нет в запасе,
корректная команда ничего не делает и не откладывается. При полном HP
`Repair` не расходуется. Поле можно сочетать с движением, наведением и выстрелом.

Параметры доступны в `state.consumableRules`; будущие моменты появления,
зерно генератора и фиксированные стартовые позиции туда не включаются.
Видимость предметов и облаков проверяется по их центрам, по тем же правилам,
что видимость танков. События реплея не передаются стратегии.
Характеристики и порядок обработки описаны в [правилах расходников](consumables.md).

## 4. Высокоуровневые команды

В JavaScript стандартная библиотека доступна как `bot`. В Python используется
`import botarena as bot`. Имена функций и ключей одинаковы; настройки в обоих
языках передаются отдельным объектом/словарём, а не именованными аргументами.

Сейчас в библиотеке доступны `scan`, `aimAt`, `holdAim`. Полностью рабочий пример:

```js
function tick(state) {
  return {
    aim: state.enemy ? bot.aimAt(state.enemy.position) : bot.scan()
  };
}
```

```python
import botarena as bot

def tick(state):
    enemy = state["enemy"]
    return {"aim": bot.aimAt(enemy["position"]) if enemy is not None else bot.scan()}
```

Примеры только управляют башней, без движения и стрельбы. Для фиксации её
угла верните `aim: bot.holdAim()`. Аргументы функций и описания команд проверяются
при исполнении; некорректная команда завершает матч ошибкой стратегии.

Следующий пример показывает будущий интерфейс навигации и проверки наведения:

```js
function tick(state) {
  return {
    move: bot.navigateTo({ x: 12, y: 3 }),
    aim: state.enemy ? bot.aimAt(state.enemy.position) : bot.holdAim(),
    shoot: !!state.enemy && bot.isAimedAt(state.self, state.enemy.position)
  };
}
```

Функции команд создают JSON-совместимые описания намерений. Они не изменяют мир
и не выполняют движение при вызове. Выполняются только команды из возвращённого
объекта. Описание движения содержит `kind` и параметры команды; описание наведения
— `kind` и точку/вектор. Эти же описания можно создать вручную.

### 4.1. Движение

| Функция | Описание команды | Поведение |
| --- | --- | --- |
| `bot.moveTo(point, options?)` | `{ kind: "moveTo", target: point, ...options }` | Ехать напрямую, поворачивать к цели и тормозить перед ней |
| `bot.navigateTo(point, options?)` | `{ kind: "navigateTo", target: point, ...options }` | Найти путь вокруг стен и следовать ему |
| `bot.followPath(points, options?)` | `{ kind: "followPath", points, ...options }` | Проходить заданные точки по порядку |
| `bot.drive(throttle, turn)` | `{ kind: "drive", throttle, turn }` | Управлять общей тягой и поворотом, значения `[-1, 1]` |
| `bot.turnTo(angle)` | `{ kind: "turnTo", angle }` | Тормозить продольное движение и доворачивать корпус к мировому углу |
| `bot.stop()` | `{ kind: "stop" }` | Тормозить движение и поворот корпуса |

Для `drive` преобразование в гусеницы: `left = throttle + turn`,
`right = throttle - turn`. Оба значения делятся на
`max(1, abs(left), abs(right))`, сохраняя пропорцию. Значения `throttle` и `turn`
сначала ограничиваются `[-1, 1]`. Для независимой тяги используется раздел 3.

Общие настройки `moveTo`, `navigateTo` и `followPath`:

| Настройка | По умолчанию | Значение |
| --- | --- | --- |
| `id` | `"movement"` | Непустая строка, идентификатор задачи внутри матча |
| `speed` | `1` | Максимальная доля скорости выбранного направления, `(0, 1]` |
| `reverse` | `false` | Проходить маршрут задним ходом, без автоматического переключения направления |
| `tolerance` | `0.2` | Допустимое расстояние до цели, больше 0 |
| `margin` | `0.05` | Дополнительный отступ от стен и границ, не меньше 0 |

Только `followPath` принимает `loop`, по умолчанию `false`. Маршрут должен
содержать от 1 до 128 точек. Первая — первая цель, текущую позицию добавлять
необязательно. Последняя точка требует остановки; промежуточная считается
пройденной при попадании в её допуск. При `loop: true` после последней снова
выбирается первая, остановка между кругами не требуется. Циклический маршрут
состоит минимум из двух различных точек и не получает статус `arrived`.

`followPath` не обходит препятствия между точками самостоятельно и не пропускает
заданную точку ради более короткого пути. Обходы задаёт игрок либо `navigateTo`.
Допуск промежуточной точки не разрешает срезать угол через препятствие.

### 4.2. Башня и стрельба

`aimAt`, `holdAim`, `scan` и низкоуровневый `shoot` реализованы.
Функция `bot.aimDirection` и `fireWhenAimed` остаются проектом; для векторного
наведения уже доступно низкоуровневое поле `aimDirection`.

| Функция/поле | Описание | Поведение |
| --- | --- | --- |
| `bot.aimAt(point)` | `{ kind: "at", target: point }` | Наводить башню на мировую точку |
| `bot.aimDirection(vector)` | `{ kind: "direction", direction: vector }` | Наводить башню по мировому вектору |
| `bot.holdAim()` | `{ kind: "hold" }` | Сохранять текущий мировой угол башни |
| `bot.scan(options?)` | `{ kind: "scan", speed: 0.5, direction: "clockwise", ...options }` | Непрерывно вращать башню в мировых осях |
| `bot.fireWhenAimed(options?)` | `{ kind: "whenAimed", tolerance: 0.03, requireClearShot: true, ...options }` в поле `fire` | Стрелять после наведения на точку из `aimAt` |
| `shoot: boolean` | Поле ответа | Та же попытка выстрела, что на низком уровне |

Если точка наведения совпала с центром танка, угол сохраняется. Упреждение,
проверка стены и решение о выстреле не добавляются к `aimAt` автоматически.
Вектор к точке вычисляется по собственному наблюдению до продвижения мира,
как при ручном расчёте `aimDirection`; новый вызов на следующем тике учитывает
изменение позиции. Изменение игроком входного `state` не меняет точку отсчёта.
`holdAim` фиксирует текущий угол сразу, как нулевой `aimDirection`; плавное
торможение вращения отдельно доступно через низкоуровневый `turretTurn: 0`.

`scan` принимает `speed` в диапазоне `(0, 1]`, долю максимальной угловой
скорости башни, и `direction`: `"clockwise"` либо `"counterclockwise"`.
Вращение продолжается через границу углов `±π`, без разворота в обратную сторону.
Начинается с фактического текущего угла; повтор команды не сбрасывает фазу.
Команда задаёт целевую угловую скорость с обычным плавным откликом механизма.
Она не расширяет видимость: в текущей игре обнаружение не зависит от башни.
При замене на `aimAt` круговое вращение прекращается, включается обычное
наведение по кратчайшему углу с соблюдением скорости и инерции башни.

`fireWhenAimed` в первой версии требует в том же ответе `aim: bot.aimAt(point)`.
С `scan`, `holdAim`, векторным наведением или без `aim` это ошибка команды:
для условного выстрела нужна явная точка проверки. `tolerance` — допустимая
угловая ошибка в радианах, диапазон `(0, π]`; `requireClearShot` — boolean.
Все настройки необязательны, значения по умолчанию приведены в таблице.

Условия проверяются после продвижения собственного корпуса и башни на шаге,
непосредственно перед обычным созданием снаряда: оружие готово, угловая ошибка
до заданной точки не превышает допуска, а коридор выстрела свободен от стен,
если запрошен `requireClearShot`. При совпадении точки с центром выстрела нет.
Коридор проверяется вдоль фактического направления ствола до расстояния от
новой позиции танка до заданной точки, с учётом размеров снаряда. Выполнение
использует эту точку и карту; скрытое состояние противника не запрашивается.
Наведение и решение не обещают попадания при изменении движения цели.

Команда действует только текущий шаг. Она не ставит выстрел в очередь:
при повторе каждый тик танк стреляет по готовности, пока условия выполняются.
`shoot: true` сохраняет возможность стрелять независимо от точности наведения.

### 4.3. Сочетание уровней и значения по умолчанию

- `move` нельзя передавать одновременно с `leftTrack` или `rightTrack`:
  это ошибка команды, даже если значение гусеницы равно нулю.
- `aim`, `aimDirection` и `turretTurn` — альтернативные способы управления
  башней; в одном ответе можно передать только один из них.
- `fire` нельзя передавать одновременно с `shoot`, включая `shoot: false`.
- Разные каналы независимы: `move` совместим с `aimDirection`, а гусеницы — с `aim`.
- Отсутствие движения эквивалентно нулевой тяге; отсутствие наведения сохраняет
  угол башни; отсутствие обоих полей стрельбы означает отсутствие выстрела.
- Высокоуровневые параметры проходят общую проверку в обоих языках. Неверный
  `kind`, тип, диапазон или неизвестный ключ описания команды — ошибка стратегии.
  Исключение по диапазону — `drive`, где применяется описанное ограничение.
- Для существующего низкоуровневого формата сохраняется текущая совместимость,
  включая ограничение тяги. Новые поля наблюдения добавляются без удаления старых.

## 5. Навигация: жизненный цикл

Навигационными задачами считаются `moveTo`, `navigateTo`, `followPath`.
`drive`, `turnTo`, `stop` — непосредственное управление без маршрутной задачи.

1. Вызов функции создаёт описание. Задача принимается после возврата из `tick`.
2. На следующем наблюдении `state.navigation` сообщает результат первого шага.
   Он никогда не описывает команду, которую игрок только собирается вернуть.
3. Повтор той же команды с тем же `id` продолжает задачу. Не сбрасываются номер
   точки, маршрут, таймер отсутствия прогресса и число попыток восстановления.
4. Смена `id` или `kind` начинает новую задачу. У `followPath` изменение точек,
   `loop`, `reverse`, `margin` или `tolerance` также начинает маршрут с первой точки.
   Изменение только `speed` сохраняет прогресс.
5. У команд с одной целью изменение координат обновляет цель той же задачи.
   `moveTo` корректирует руление сразу; правила перестройки `navigateTo` ниже.
6. Отсутствие движения, гусеницы или непосредственная команда отменяют задачу.
   В следующем наблюдении она имеет статус `cancelled`, затем `idle`, если новая
   навигационная задача не началась. Новая задача сразу заменяет старый статус.
7. Завершённая задача с неизменной целью остаётся `arrived` при повторе, продолжая
   тормозить. Если танк вышел из допуска, она снова становится `moving`.
8. `blocked` и `unreachable` сохраняются при повторе неизменной задачи: бот
   тормозит и не запускает бесконечные попытки. Изменение цели/маршрута либо новый
   `id` запускает новую попытку. После отмены тот же `id` можно использовать снова.

Для `navigateTo` изменение `reverse`, `margin` или `tolerance` требует нового
плана; для `moveTo` параметры применяются сразу. Значения сравниваются по
содержимому, создание нового объекта JavaScript/Python не перезапускает задачу.

### Статусы `state.navigation`

```js
{
  id: "movement",          // null в idle
  kind: "navigateTo",      // null в idle
  status: "moving",
  reason: null,
  target: { x: 12, y: 3 },  // текущая конечная цель; null в idle
  waypointIndex: 0,         // индекс следующей точки route; null, если точек нет
  route: [{ x: 4, y: 3 }, { x: 12, y: 3 }]
}
```

`route` — текущие путевые точки без стартовой позиции. У `followPath` это
заданные игроком точки; у `navigateTo` — построенный маршрут; у `moveTo` — одна
цель. После достижения цели `waypointIndex = null`. При `cancelled` возвращается
последний снимок отменённой задачи. Первое наблюдение матча — `idle` с пустым `route`.

| Статус | Значение | Причины `reason` |
| --- | --- | --- |
| `idle` | Навигационной задачи нет | `null` |
| `moving` | Танк едет, поворачивает, тормозит или кратковременно ждёт прохода | `null`, `waitingForObstacle` |
| `arrived` | Конечная цель достигнута и продольная скорость не больше `0.05` по модулю | `null` |
| `blocked` | Исполнение не продвигается либо исчерпан бюджет поиска | `directPathBlocked`, `dynamicObstacle`, `stuck`, `searchLimit` |
| `unreachable` | Безопасный маршрут не найден в принятой модели проходимости | `targetOutsideArena`, `insufficientClearance`, `noPath` |
| `cancelled` | Задача отменена командой игрока | `null` |

`blocked` и `unreachable` — штатные результаты, они не завершают матч.
Неконечная координата — ошибка стратегии; конечная точка за пределами арены —
`unreachable`. Нельзя молча подменять конечную цель ближайшей свободной клеткой.
У `followPath` все точки проверяются при принятии маршрута; перекрытый стеной
сегмент даёт `blocked/directPathBlocked` до начала движения.
`moveTo` так же проверяет прямой коридор и при его перекрытии возвращает
`blocked/directPathBlocked`, не пытаясь доехать до самой стены.

## 6. Навигация: препятствия и движение

### 6.1. Геометрия проходимости

Для встроенной навигации корпус консервативно покрывается окружностью радиуса
`R = hypot(botLength, botWidth) / 2`. От стен и границ требуется отступ
`R + margin`. При текущем корпусе `0.68 × 0.58` радиус примерно `0.447`.
Проход должен вмещать диаметр этой окружности и запас с обеих сторон.

Проверяется весь отрезок движения центра, а не только клетка назначения.
Касание границы безопасного коридора считается перекрытым проходом.
Эта модель оставляет место для разворота, но может отвергнуть узкий проход,
который прямоугольный корпус способен пройти при определённой ориентации.
Игрок может написать собственный планировщик и использовать низкий уровень.

Если начальная или конечная позиция не имеет нужного отступа, встроенный
планировщик возвращает `unreachable/insufficientClearance`. Он не пытается
самостоятельно выехать из тесного положения. Игрок может отъехать гусеницами,
снизить дополнительный `margin` и повторить запрос.

### 6.2. Поиск маршрута `navigateTo`

1. Проверить прямой проход. Если он свободен, выбрать прямой маршрут.
2. Иначе выполнить A* по сетке с шагом `0.2` единицы арены, восемью соседями,
   евклидовой стоимостью и эвристикой. Узлы сетки имеют координаты, кратные шагу;
   используются только узлы внутри безопасных границ арены.
3. Старт и точную цель добавить отдельными узлами, соединёнными со свободными
   вершинами содержащей их клетки, если весь соединяющий отрезок проходим.
   Непроходимые диагонали и срезание углов запрещены.
4. Упростить путь, соединяя наиболее дальние видимые путевые точки, если
   безопасен весь коридор. Точную конечную цель сохранить.
5. Не исследовать больше `20 000` узлов за один поиск: превышение даёт
   `blocked/searchLimit`, исчерпание доступных узлов — `unreachable/noPath`.

Сетка и предел поиска — настройки встроенного алгоритма, не параметры каждой
команды. Узлы с одинаковым приоритетом обрабатываются в фиксированном порядке,
чтобы одинаковые наблюдения и команды давали одинаковые маршруты.

Маршрут к неизменной цели кэшируется. Для движущейся цели он перестраивается,
когда цель отдалилась от последней запланированной больше чем на
`max(0.2, tolerance)`, либо прежний коридор перекрыт. Перестройка выполняется
не чаще раза в `0.5` игровой секунды. Если обновлённый прямой отрезок безопасен,
конечную точку можно обновить без A*. Достижение проверяется относительно
актуальной цели; при устаревшем плане и небезопасном продолжении танк тормозит
до разрешённой перестройки. Изменение цели не обнуляет таймер застревания,
кроме выхода из терминального статуса по правилам раздела 5.

### 6.3. Контроллер движения

- Корпус разворачивается в сторону следующей точки; при `reverse: true` —
  противоположной стороной. Задний ход использует `maxReverseSpeed`.
- Перед большим поворотом снижается тяга. Продольная скорость ограничивается
  настройкой `speed`, расстоянием до точки, угловой ошибкой и тормозным путём.
- На конечном участке контроллер тормозит заранее, учитывая `deceleration`
  и минимум один шаг реакции. Внутри допуска задаёт нулевую тягу и дожидается
  выполнения условия `arrived`. При выезде из допуска корректирует положение.
- Следующий шаг проверяется на безопасность с учётом текущей скорости и
  скорости поворота. Если безопасную команду подобрать нельзя, задаётся
  торможение; перестановка координат или обнуление физической скорости запрещены.
- Финальное решение о столкновении всегда принимает обычная физика `Duel`.
  Навигация снижает вероятность столкновения, но не гарантирует отсутствие
  контакта при вмешательстве другого танка или смене команды на скорости.

### 6.4. Подвижные препятствия и застревание

Статический маршрут строится по стенам. Видимый противник дополнительно
учитывается локальным контроллером как окружность корпуса: проверяется
прогноз сближения на ближайшие `0.3` секунды по его наблюдаемым позиции,
`bodyAngle` и `speed`. Данные скрытого противника не используются.
Прошлое наблюдение автоматически не превращается в актуальную преграду.
Снаряды не меняют маршрут; уклонение программирует игрок.

При опасном сближении контроллер тормозит с `moving/waitingForObstacle`.
После `0.5` секунды ожидания `navigateTo` пробует найти обход, учитывая текущую
видимую позицию противника как временную преграду. Кэш такой преграды удаляется
при потере видимости. Если обход не найден, танк продолжает ждать в пределах
общего срока восстановления; это не `unreachable` статической карты.
`moveTo` и `followPath` самостоятельно обходной маршрут не строят.

Если активный участок не уменьшил расстояние до следующей точки хотя бы на
`0.05` за `1` секунду, начинается восстановление. Чистый разворот считается
прогрессом, если за это окно угловая ошибка уменьшилась хотя бы на `0.05` радиан.
Ожидание подвижного препятствия также учитывается в сроке отсутствия прогресса.
Навигация тормозит и пытается перестроить путь, если команда это допускает.
Не более трёх перестроек и не более `2` секунд восстановления без прогресса;
после первого исчерпанного ограничения — `blocked/dynamicObstacle` при видимом
блокирующем танке либо `blocked/stuck`. Новая перестройка не сбрасывает срок.
Подтверждённое продвижение или переход к следующей точке сбрасывают окно
контроля и попытки восстановления. Автоматический таран или откат назад
в процедуру восстановления не входят.

## 7. Запросы и вспомогательные функции

Запросы не изменяют задачу и работают только с переданным наблюдением.

| Функция | Результат |
| --- | --- |
| `bot.distance(a, b)` | Евклидово расстояние между точками |
| `bot.angleTo(a, b)` | Мировой угол от `a` к `b`; при совпадении точек — `0` |
| `bot.angleDifference(a, b)` | Нормализованное `a - b` в `[-π, π]` |
| `bot.isAimedAt(self, point, tolerance = 0.05)` | Угловая ошибка башни не больше допуска; при совпадении точек — `false` |
| `bot.predictIntercept(state, target)` | Точка встречи снаряда с наблюдаемой целью либо `null`, если допустимого решения нет |
| `bot.hasClearShot(state, point)` | Прямой коридор от текущего центра своего танка до точки свободен от стен с учётом размеров снаряда |
| `bot.hasLineOfSight(state, a, b)` | Стены не пересекают отрезок между точками; размеры танка и снаряда не учитываются |
| `bot.canMoveTo(state, point, options?)` | Свободен прямой коридор от `self.position` до точки |
| `bot.findPath(state, point, options?)` | `{ status: "found", points }` либо `{ status: "unreachable" или "blocked", reason, points: [] }` |

`canMoveTo` и `findPath` принимают только `margin`, по умолчанию `0.05`;
геометрия, сетка и причины отказа совпадают с навигацией. Они учитывают стены
и границы, но не противника, тормозной путь или возможность немедленного
разворота из текущего состояния. `canMoveTo` возвращает `false` для точки вне
арены. `findPath` возвращает точки без стартовой позиции, с точной целью в конце;
совпавшие свободные старт и цель дают `found` и одну точку.

Функции поиска подчиняются тому же пределу узлов; каждый запрос учитывается
в бюджете вычислений стратегии. Нельзя делать неограниченное число запросов
за тик. Встроенные поиск и контроллер выполняются в рабочем процессе матча,
ограничены общим дедлайном и используют только наблюдение конкретного бота.
Оба языка должны получать одинаковый результат встроенного планировщика.

`hasLineOfSight` не является проверкой проходимости корпуса или гарантией
попадания снаряда. Все функции проверяют конечность чисел; ошибочные типы
вызывают ошибку стратегии. Точки вне арены для `hasLineOfSight` недопустимы.

`predictIntercept` принимает наблюдаемое состояние танка. Скорость цели
вычисляется как `speed * { cos(bodyAngle), sin(bodyAngle) }`. Решается задача
перехвата при постоянной скорости цели и `rules.bulletSpeed`; выбирается
минимальное положительное время встречи. Учитывается и вырожденный линейный
случай. Начало полёта — текущий центр своего танка, как в существующей модели
создания снаряда; скорость собственного корпуса снаряду не добавляется.
Если положительного решения нет, точка вне арены или время встречи превышает
оставшееся время матча, возвращается `null`. При `target: null` — также `null`.
Поворот башни, будущее ускорение, разворот и столкновения цели не предсказываются;
поэтому прогноз пересчитывается каждый тик, а не один раз при обнаружении.

`hasClearShot` проверяет коридор к точке по текущему наблюдению, без продвижения
мира. Для совпавшей с центром точки или точки вне арены возвращает `false`.
Он не проверяет направление башни или готовность оружия. В отличие от него,
`fireWhenAimed` оценивает фактический ствол после поворота на текущем шаге.

## 8. Примеры перехода между уровнями

### Базовый сценарий новичка: патруль, обзор и прицельная стрельба

Патруль выполняется постоянно, включая время наведения и стрельбы. Он не
отменяется при появлении противника, поэтому не теряется индекс маршрута.
Подготовленный маршрут ниже подходит текущей карте Classic и старту игрока;
для другой карты точки нужно подобрать заново. Встроенной генерации патруля
в этой версии нет. Матч может закончиться раньше полного круга.

```js
const patrol = [
  { x: 2, y: 1 },
  { x: 14, y: 1 },
  { x: 14, y: 9 },
  { x: 2, y: 9 }
];

function tick(state) {
  const action = {
    move: bot.followPath(patrol, {
      id: "patrol", loop: true, speed: 0.7
    }),
    aim: bot.scan()
  };

  if (state.enemy !== null) {
    const point = bot.predictIntercept(state, state.enemy);
    action.aim = bot.aimAt(point ?? state.enemy.position);
    if (point !== null) action.fire = bot.fireWhenAimed();
  }

  return action;
}
```

| Ситуация | Движение | Башня | Стрельба |
| --- | --- | --- | --- |
| Враг не виден | Продолжать патруль | Вращаться по кругу | Нет |
| Враг виден, прогноз получен | Продолжать патруль | Наводиться на обновляемую точку упреждения | По готовности, после наведения и проверки коридора |
| Враг виден, перехват не рассчитан | Продолжать патруль | Следить за текущей позицией врага | Нет |
| Враг исчез за стеной | Продолжать патруль | Возобновить вращение с текущего угла | Нет; отложенного выстрела не остаётся |

Приоритет наведения выше вращения: в ответе всегда одна команда `aim`.
«Быстро навестись» означает использовать обычную максимальную скорость
механизма, а не мгновенно поставить угол. Перезарядка не мешает сопровождать цель.
Патруль подчиняется штатным отказам `followPath`: при блокировке танк тормозит,
статус доступен в `state.navigation`, автоматический таран не выполняется.
Новичок может начать с примера, затем поменять маршрут, скорость, допуск
стрельбы или самостоятельно заменить расчёт упреждения.

### Первая стратегия: доехать к позиции и стрелять по видимой цели

```js
function tick(state) {
  const enemy = state.enemy;
  return {
    move: bot.navigateTo({ x: 10, y: 3.5 }),
    aim: enemy ? bot.aimAt(enemy.position) : bot.holdAim(),
    shoot: !!enemy && bot.isAimedAt(state.self, enemy.position)
  };
}
```

### Свой маршрут с обработкой отказа

```js
// Обход верхней стены на текущей карте Classic от стартовой позиции игрока.
const route = [{ x: 3.5, y: 1 }, { x: 7, y: 1 }, { x: 10, y: 3.5 }];
let phase = "flank";

function tick(state) {
  const failed = state.navigation.id === "flank" &&
    ["blocked", "unreachable"].includes(state.navigation.status);
  if (failed) phase = "hold";
  return {
    move: phase === "hold" ? bot.stop() : bot.followPath(route, { id: "flank" }),
    aim: state.enemy ? bot.aimAt(state.enemy.position) : bot.holdAim()
  };
}
```

После отмены отказавшая задача может стартовать снова. Для постоянного перехода
к другой тактике нужно сохранить фазу в памяти, а не вычислять её только по
одному статусу. В обоих примерах отказ переводит стратегию в режим удержания.

```python
import botarena as bot

phase = "advance"

def tick(state):
    global phase
    nav = state["navigation"]
    if nav["id"] == "advance" and nav["status"] in ("blocked", "unreachable"):
        phase = "hold"

    return {
        "move": bot.navigateTo({"x": 10, "y": 3.5}, {"id": "advance"})
            if phase == "advance" else bot.stop(),
        "aim": bot.aimAt(state["enemy"]["position"])
            if state["enemy"] is not None else bot.holdAim(),
    }
```

### Полное управление гусеницами с удобным наведением

function tick(state) {

## 9. Границы первой версии и критерии реализации

В навигационный v1 входят команды и запросы разделов 3–7. Обсуждавшиеся
`keepDistance`, `orbit`, `retreatFrom`, поиск укрытий и уклонение от снарядов
остаются будущими библиотечными поведениями; их интерфейс пока не фиксируется.
Игрок уже сможет собрать такие алгоритмы из маршрутов, геометрических запросов
и низкоуровневого управления. Новые режимы боя не входят в эту спецификацию.

При реализации проверить:

- Совместимость старых стратегий; одинаковую валидацию JS/Python; смешение
  разных каналов и отказ при конфликтующих командах одного канала.
- Прямой путь, объезд одной и нескольких стен, запрет срезания углов,
  границы арены, узкий проход, недопустимую цель и исчерпание поиска.
- Торможение у цели с разных скоростей, движение задним ходом, переходы между
  точками, остановку в конце и повтор циклического маршрута.
- Продолжение задачи при новом объекте команды, обновление движущейся цели,
  ограничение частоты поиска, отмену, новый `id`, перезапуск после отказа
  и отсутствие самопроизвольного рестарта завершённой задачи.
- Блокировку противником, потерю его видимости, отсутствие утечки скрытых
  координат, ограниченное восстановление и устойчивые терминальные статусы.
- Выезд из допуска после `arrived`, старт вплотную к стене, управление на
  скорости и независимость башни/стрельбы от навигации.
- Одинаковый путь встроенного поиска для JS/Python и неизменность физики при
  выборе высокого уровня. Работу в пределах общего дедлайна рабочего процесса.
- Базовый патруль без сброса точки при обнаружении/потере врага; круговое
  вращение через `±π` и переключение на наведение без превышения скорости башни.
- Упреждение для неподвижной цели, поперечного движения, заднего хода,
  отсутствующего и вырожденного решения; отсутствие обращения к скрытой цели.
- Запрет выстрела до наведения, во время перезарядки и при перекрытом коридоре;
  проверку угла после поворота башни, потерю цели без отложенного выстрела,
  конфликт `fire`/`shoot` и несовместимое наведение с `fireWhenAimed`.

Реализованные возможности перечислены в начале документа и справке редактора.
При реализации остальных функций нужно обновлять обе отметки готовности.
